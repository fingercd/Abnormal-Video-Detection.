# 01｜从正常—异常输入差异出发的 ViT 性质探索与插件决策

> 文档版本：2026-09-17 / 本轮需求重写。读者：研究负责人、Codex、执行实验的 agent。
> 本文是待执行研究协议，不是实验报告。没有任何“异常一定高方差／低熵／低冗余”的预设结论。
> 代码依据：本次上传的 `VAD_code_20260917_210441.zip` 和 `codebase-overview-2026-09-17.md`。不以 `VAD_Idea/`、先前 Ideas 仓库或旧版研究指南作为方法依据。

## 0. 唯一研究主轴

**把正常视频与异常视频输入同一个冻结 ViT encoder，比较中间 token 的分布、时空关系、Q/K/V 交互、全局读出和跨层／跨头演化；从可重复的差异中提炼低成本的 token 预算、保留或合并规则，最终验证保持异常检测质量的加速与显存收益。**

本项目中，“重要性”统一用作**当前异常检测任务下的 token 处理优先级**。不开展“重要性与可压缩性是否同义”的概念争论。优先级既可作用于单 token，也可作用于 token 对、token 组、时间位置或某层预算。

需要回答的是四个连续问题：

1. 正常与异常输入之间，究竟哪种性质有差异？差异是整体性的，还是只在局部、尾部、某类异常或某些层中出现？
2. 这种差异能否在推理时不读取真值、不运行完整教师的前提下被识别？
3. 根据该性质分配 token 或合并 token，是否比相同预算下的随机、均匀或通用策略更合适？
4. 同一条规则在多个 encoder 和独立数据上，是否保持检测质量并产生实际净收益？

第一轮不开发最终插件。先形成“差异证据 → 对照 → 可部署信号 → 最小操作验证”的记录。最终算法、方向符号、压缩位置、是否训练，由记录决定。

## 1. 先把“异常输入”定义清楚

### 1.1 三种比较，分开保存

| 比较代码 | 分组 | 能回答的问题 | 不能自动推断的内容 |
|---|---|---|---|
| C1 / weak-video | 正常视频 V− vs 异常视频 V+；两组使用相同采样规则 | 两类视频的 token 性质分布是否不同 | V+ 的每一帧、每个 token 都异常 |
| C2 / event-paired | 同一视频中，可靠时间标注内 A vs 标注外 B；B 避开事件边界和不确定区域 | 同场景内的差异是否与事件出现相关 | 整段 A 的全部空间 token 是异常区域；B 一定完全正常 |
| C3 / matched-control | A 或 V+ vs 场景、亮度、运动等有记录的正常对照 N | 差异是否只是容易混淆的输入因素造成 | 控制掉运动以后剩余的差异才是唯一真实异常信息 |

C1 是默认的严格弱监督开发路径。C2 需要可靠时间标注，属于单独的诊断轨。C3 同时报告匹配前和匹配后的结果，避免把真实事件伴随的运动变化也全部“控制掉”。

### 1.2 两条标注使用路径

**路径 W：严格弱监督研发主线。**只用官方训练视频级标签建立 C1，正常训练视频作为正常参照；从官方训练划出独立确认与选择集。最终测试时间标注只在方法冻结后用于检测评估和 C2 机制复核。此时开发阶段只能把 V+ 中的位置称为“正视频中的候选位置”，不能称为真实异常 token。

**路径 D：有明确披露的标注辅助探索。**若研究负责人提供独立开发数据的可靠事件区间，可以从第一轮做 C2。记录数据来源、谁标注、是否参与方法／阈值选择。即使训练损失只用视频级标签，只要这些细粒度标注影响了方法设计，也应披露“标注辅助研究设计”，不能声称整个开发过程从未接触细粒度信息。

不默认让 Codex 自行观看官方测试异常区间后调算法；不把伪标签写成真实标注；不把 UCA 的任意 caption 时间段直接映射成异常区间。

### 1.3 建议的首轮样本规模：只是起始预算，不是充分性的保证

- **调试集：4 个 V+、4 个 V−**，每个视频均匀取 8 个时间窗口。目标是检查张量、坐标和图，不做统计结论。
- **探索集：64 个 V+、64 个 V−**，每视频取 8–12 个窗口，来自训练拟合集；类别、时长、场景尽量分层。实际不足时记录原因，不重复同一视频凑独立样本数。
- **独立确认集：建议 32 个 V+、32 个 V−**，来自预先保留的训练确认分区，不参与性质筛选、拟合原型和方向选择。
- **可选配对诊断：20–30 个有合法事件区间的视频**，每个含 A、事件前 Bpre、事件后 Bpost，再匹配外部正常 N。没有可用标注则不创建这个分组。

窗口由原视频时间确定。不同 encoder 可以按各自已验证输入 profile 在同一时间窗口采样；跨 encoder 比较的是效应方向、相对深度和标准化效应，不把不同帧数／分辨率下的绝对方差或延迟直接相减。

### 1.4 数据划分和伪标签

建议从官方训练视频按视频 ID 分层形成 `fit / confirm / select`，初始比例可用 80/10/10。`explore` 是 `fit` 的固定子集，不是第四个重叠后又声称独立的分区。调试集是 explore 子集。

若用 MIL 高分位置丰富 V+ 采样，额外产生 `pseudo_positive` 字段，保留同视频均匀采样结果，避免“根据一个分数选样，再证明该分数高”的循环。可在已缓存 pooled features 上用跨折检测头生成 out-of-fold 分数；不用空间或时间真值训练它。未做跨折时如实标注。

## 2. 从模型哪里取数据

### 2.1 第一轮只选一个主 encoder

先用当前已经跑通的 `videomaev2` 检查观察链路；随后在 `timesformer` 上确认结构差异；最后扩展到 `vjepa2` 和 `videomae`。具体四个配置与受保护边界见文档 02。

每个模型写一份 `architecture_receipt.json`，至少包含：

```text
encoder_id, checkpoint_revision, loaded_weights_digest, implementation_revision
input_layout, processed_shape, precision, attention_backend
patch_size, tubelet_size, token_order, position_scheme
num_blocks, num_heads_per_block, head_dim, special_token_indices
has_cls, native_readout, adapter_readout
block_paths, attention_paths, qkv_paths, mlp_paths
observation_sites, supports_variable_tokens, structural_constraints
```

这些字段从当前实际加载模型读取，不能由名字猜测。比如 `CLS` 是否存在、最终是否用 CLS 池化，都需要确认。

### 2.2 分层采集位置

在 embedding 输出和约 25%、50%、75%、100% 深度采样。12 个 block 的模型可从 embedding、block 3/6/9/12 后开始；代码用明确的 0-based 模块索引保存，不将“第 3 层”混成索引 3。邻层稳定性需要时额外采相邻一层，不默认每层全量 dump。

每个选中 block 取：

- `X_in`：进入该 block 的 token。
- `X_ln`：attention 前实际 LayerNorm 输出。
- `Q, K, V`：真实 attention 使用的投影；同时注明是否经过 Q/K norm、RoPE 或相对位置处理。
- `A_sample`：指定 query 行对全部合法 key 的 attention 分布。
- `U_attn`：attention 分支在输出投影后、残差相加前的更新。
- `U_mlp`：MLP 分支在残差相加前的更新。
- `X_out`：block 输出。
- `C_l / Z_l`：真实 CLS 或明确命名的诊断 pooled vector；两者不能互换命名。

TimeSformer 的 spatial 与 temporal 子层分开标记；native HF attention 返回值与代理重建 attention 分开标记。

### 2.3 两种观察成本模式

**轻量模式**只采固定数量 token、token 对、在线统计与小图，默认最多 256 个 patch token 用于谱和图计算。空间／时间分层抽样，正常和异常使用同一抽样方案。标记这是“样本 token 谱”，不是完整网络秩。

**深入模式**对固定小子集获取每头 32–64 个 query 的 attention 行，沿完整 key 轴归一化。不能截一小块 QK 后重新 softmax，再把结果叫全局 attention entropy。若只有部分 key，须单独命名为局部近似指标。

采集端立即计算摘要并转 CPU；只保留指定案例的数组；不在 GPU 列表累计所有层张量。只读 hook 必须在 `finally` 中移除，返回值不得改动原前向。正式速度测试完全关闭这些探针。

## 3. 六个观察方向与 18 个具体探针

每个探针都要求：C1 正负视频分布；可用时 C2 同视频配对；C3 混淆控制；按 encoder、相对层深和异常类别分层；最后才考虑映射到插件。

### 方向 A：token 数值分布和表征维数

#### P01｜激活强度、离散度和尾部比例

**取什么：**`X_in` 和 `X_out`，去掉特殊 token 与 padding。每个 token 的尺度取 `a_i=||x_i||₂/sqrt(D)`；比较 clip 内中位数、IQR、p95/p50，以及 token 间每通道方差的均值。若 p50 近零则不输出比值，另记 degenerate。

**怎么比：**画逐层的 V+、V− 分位曲线，额外画异常视频的“每个时间窗口统计量”，不只报告整视频均值。C2 看事件前—中—后的变化；C3 加高运动正常、低光正常等对照。

**为何如此测：**LayerNorm 的归一化机制会直接影响每个 token 的通道均值和方差；不能把归一化后接近常数的方差当作没差异，也不能把数值精度变化当作异常性质。将 pre-LN 和 post-LN 结果分开。

**可能的操作：**若差异在少数位置的尾部而非整体，可研究分层抽样／尾部保留与主体聚合；若整体一致，则不把幅值当主信号。方向由训练探索集确定，不能预设保留大范数。

#### P02｜token 协方差谱、有效维数与代表数量

**取什么：**固定数量 n 个 token，对各通道减 token 均值形成 `Xc`，得到奇异值 `σj`，以 `λj=σj²` 归一化：

```text
pj = λj / sum(λ)
r_eff = exp(-sum(pj * log(pj)))
r90 = 累计 λ 达到 90% 所需的最小维数
r_eff_norm = r_eff / min(n-1, D)
```

全零 Xc 的有效维数设为 0 并记录退化。用相同 n、相同中心化和精度比较，不能对每组单独做不同 PCA。

**怎么比：**C1 比较分布及层曲线；C2 看事件期间谱形是否变化；将全 clip 与局部时空组分开。随后测量相同代表比例下的重建／覆盖误差，但不把特征重建误差等同于最终检测精度。

**可能的操作：**若局部代表需求随输入性质变化，可研究局部 token 配额；若多个层形成一致低维结构，可研究代表合并或分阶段缩减。PCA 只是诊断，不默认把在线 PCA 做进插件。

#### P03｜相对正常参照的分布偏离

**取什么：**只用 `fit` 中正常视频，在每个 encoder/层拟合有限原型或低秩加收缩的协方差；对所有输入测量到正常参照的距离分布、局部高偏离比例及时间持续性。

**怎么比：**重点不是“异常距离大”，而是检验偏离来自异常事件还是新场景。分开报告同场景匹配、跨场景、正常高运动、正常低光；记录异常类别间的异质性。

**可能的操作：**若偏离稳定且与任务有关，可把它变成优先级／预算信号；若只识别新场景，则只能作场景性质，不能命名为异常证据。

**监督口径：**这类方法需要训练正常样本的校准，即使无梯度，也不是 data-free。不能用测试正常视频拟合参照。

### 方向 B：空间 token 对与 token 组的关系

#### P04｜局部／非局部相似度、冗余占比和覆盖曲线

**取什么：**L2 归一化 token 的余弦相似度。分别采“同帧近邻”“同帧远邻”“相邻时间对应位置”的 token 对；排除 self、padding 和重复采样帧。比较相似度分布、最近邻距离以及给定 K 个代表的覆盖曲线。

**怎么比：**正常与异常输入在相同空间距离、相同运动层级下比较；不要让正常组大多是邻居对、异常组大多是远距离对。

**可能的操作：**若正负输入的局部组结构不同，可研究组内合并、组间保留；若只有局部稀疏位置不同，可让少量位置独立、其余位置共享代表。先验证“哪种组”而不是预设背景组。

#### P05｜关系图的社区、桥接与跨区域连接

**取什么：**在固定 n 个 sampled token 上构造同一规则的 kNN 图，比较组内相似度、跨组边权、节点连接分布、连通分量及其随时间的变化。k 是预先固定的诊断参数，不为正负组分别选择。

**怎么比：**检查单 token 数值相近时，正负组是否仍表现出关系结构差异。图的社区是表征社区，不等于“人”“车”“异常主体”。没有空间真值时不赋予语义名字。

**可能的操作：**若跨组关系比单 token 幅值更能解释差异，可以研究“组代表＋少量连接位置”的 token 保留，而不是所有社区只留一个平均值。在线全图构建太贵时再寻找局部代理。

#### P06｜关系差异是否超出简单相似度

**取什么：**对特征余弦相似度接近的 token 对，比较它们的时间轨迹差异、attention 接收模式差异与后续更新差异；按相似度区间匹配。

**怎么比：**正常视频与异常视频是否在“相似外观，但交互不同”的 token 对比例上不同？同时比较随机对、距离匹配对。

**可能的操作：**若关系信号带来额外区分能力，合并准则可由单一 feature similarity 扩展为 feature＋interaction；若无额外收益，就保留简单基线。

### 方向 C：时间变化与时空持续性

#### P07｜同位置与局部对齐后的时间变化

**取什么：**相邻时间 token 的 `1-cos(x[t,p], x[t+1,p])`；再计算局部搜索邻域内最佳／互相最近邻匹配后的差异。按实际采样时间间隔分别报告，不把帧率差异解释为异常变化。

**怎么比：**高运动正常与低运动异常单列；存在镜头切换或相机移动的窗口另设标志。既看中位变化，也看高变化区域占比和持续长度。

**可能的操作：**若大部分区域持续稳定、差异只在部分轨迹出现，可以研究稳定区域的时间合并；若相邻位置变化主要由相机移动解释，则优先用局部对齐或放弃该信号。

#### P08｜新关系出现的频率与生命周期

**取什么：**每个位置的近邻集合、相邻窗口 token 的匹配关系，统计 Jaccard、匹配失效率、同组连续持续时长。共享关系的定义固定，不根据异常标签改变。

**怎么比：**V+ 与 V− 的关系生命周期分布；有标注时 A、Bpre、Bpost 的配对变化；同一事件期间是否持续，还是一次镜头切换即结束。

**可能的操作：**关系可复用时减少匹配次数；变化更快的输入采用更短的路由刷新间隔。初版限定在一个 clip 内，不自动升级到跨 clip cache。

#### P09｜局部变化在整段视频中的占比与聚集性

**取什么：**将 P01/P04/P07 的局部统计按时间拼接，计算固定参考阈值超出比例、连续段长度与时间集中度。阈值来自 fit，不能分别对每个 clip 取 top 10% 后再宣称异常组“高值占比更大”——那样比例本来就固定。

**怎么比：**比较正负视频的变化是持续、短暂还是散落。与视频总长度、解码帧数、有效窗口数匹配。

**可能的操作：**输入自适应时间预算或局部 token 配额。推理时只能由观测信号决定，不能读取视频标签、类别目录或真值事件时间。

### 方向 D：Q/K/V、attention 和信息汇聚

#### P10｜每个 query 请求信息的集中程度

**取什么：**真实 attention 行 `A[h,i,:]`，计算

```text
H_out(h,i) = -sum_j A[h,i,j] log A[h,i,j] / log(N_valid_keys)
```

并计算 top-k attention mass、远时空位置的质量占比。N=1 的行单独处理。融合 kernel 无 attention 输出时，可重建指定 query 行，但必须包含真实缩放、位置偏置、mask、QK normalization，并在小样本核对输出。

**怎么比：**比较 C1/C2/C3 中 H 的分布和异常类别异质性。绝不预设异常更分散或更集中。

**可能的操作：**若部分 token 请求模式可合并，可研究相同交互组的 token 合并；若部分 token 需要独立上下文，则给它们独立代表。以实际结果决定方向。

#### P11｜哪些 token 被读取，以及读取分布是否不同

**取什么：**对均匀采样的 query 行计算 `p_in(j)=mean_i A[i,j]`，它沿 key 轴和为 1；比较该分布的熵、top-mass、Gini、空间／时间位置和跨层变化。若 query 不是均匀抽样，必须修正采样权重或标为局部统计。

**重要检查：**完整 attention 的所有元素平均值是由行归一化约束的 `1/N`，通常不是有意义的正负差异。incoming mass 的均值也受约束，研究的是其分布。

**怎么比：**正常与异常是否形成不同的汇聚模式？被大量读取的位置是否稳定属于特殊 token、边缘、图像文字或固定场景？不要直接把高 incoming mass 叫异常位置。

**可能的操作：**优先级加权的 token 代表选择、保留特定汇聚位置，或对同角色来源聚合。相关的逆注意力压缩已有文献，不能仅靠反转分数就宣称新颖 [R4]。

#### P12｜K/V 分布与 token 的实际输出贡献

**取什么：**每头 K、V 的范数和协方差谱；Q/K 与位置信息分别标识。用少量 query 估计组贡献 `sum_{j in G} A_ij V_j`，并经对应输出投影映射到公共维度后比较。

**怎么比：**相似 K 是否对应相似 V？正负输入的同组贡献是否更集中／更分散？是否出现方向抵消？只比较 K 范数不等于比较信息贡献。

**可能的操作：**K/V 或整 token 的分组聚合。只压 K/V 不会自动减少全部 MLP 计算；优先验证该关系能否转化为真正减少后续 token 数的方案。

**KV cache 口径：**四个默认 encoder 是固定 clip 路径。本项目这里测的是 attention 的 K/V 激活，不是语言模型的持久 KV cache。只有真实存在跨 step 可复用状态，才新增 cache 生命周期探针；不为迎合题目伪造 cache。

### 方向 E：CLS、全局读出与类别条件分布

#### P13｜真实 CLS 如何聚合 patch 信息

**取什么：**有真实 CLS 时，记录其每层状态变化、CLS→patch attention、patch→CLS attention，以及汇聚质量的时空分布。分别记录骨干 native readout 和当前 adapter readout。

**怎么比：**V+ 与 V− 的 CLS 汇聚集中度、层间方向变化和局部贡献分布；异常类别分层。

**可能的操作：**若 CLS 读出与任务差异相关，可以研究读出引导的 token 选择；但必须提供不依赖 CLS 的等价统计定义，否则不是同一个跨 encoder 插件。

**无 CLS：**跳过 CLS 探针并记 `not_applicable`，改看明确命名的 `pooled_readout`。不能把第一个 patch 假装成 CLS，也不应为了观察新增一个未训练 CLS。

#### P14｜少量 token 组能否保持全局及异常判别读出

**取什么：**先用 mean/native pooled feature，后用只在 fit 视频级标签训练的统一 MIL head。对 P04/P05 定义的组进行小规模“保留代表／按质量合并”实验，测 pooled feature、视频级预测和时序分数变化。

**怎么比：**正常与异常分别报告，同时比较相同 K 的随机、均匀和相似度合并。把“保持正常低分”和“保持正视频判别”一起检查，不只看正样本。

**可能的操作：**任务读出约束的 token 合并。该实验是从性质到操作的验证，不预设压缩损伤，不要求发生分数下降才算有结果。

**边界：**当前代码的 attention MIL 是 gated pooling，不是 Transformer encoder；`TemporalSupervisedHead` 不是现成的弱监督时序 Transformer。不要误用强监督标签。

#### P15｜不同异常类别是否共享同一种差异

**取什么：**为 P01–P14 的候选统计绘制类别条件分布；记录在若干类别上同向、在另一些类别上无效或反向的情况。类别仅用于分析分层，不作为线上插件输入。

**怎么比：**从一个异常类别发现性质，在未参与发现的类别、正常硬例以及第二数据集上复核。样本稀少类别只作描述，不强报显著性。

**可能的操作：**若单一分数方向不通用，研究不依赖类别名的混合统计或局部配额，而不是在线读取“Fighting/Normal”文件夹来决定保留率。

**class 的另一种含义：**有原生动作分类头时，其类别概率、熵、margin 可以作为可选诊断。但 Kinetics 类别置信度不是异常概率；没有分类头就不为了该探针临时新增训练任务。

### 方向 F：跨层演化与多头分工

#### P16｜性质差异在哪些层形成、增强或消失

**取什么：**追踪每个 clip 的 P01/P02/P04/P10/P11 随深度的轨迹；同时记录 `||U_attn||/||X_in||`、`||U_mlp||/||X_mid||` 和局部更新方向。

**怎么比：**正负轨迹差异、C2 事件内外轨迹差异、同一输入换 encoder 后的相对深度差异。hidden state 稳定也可能只是残差占主导，所以必须同时看分支更新。

**可能的操作：**按性质出现阶段安排一次或多次压缩；不预设越深越可压、不预设所有模型第 3/6/9 层通用。

#### P17｜正常与异常是否激活不同的多头协同模式

**取什么：**同一 query 位置的各头 attention 分布 JS divergence；各头 `O_h=(A_h V_h)W_O^h` 在公共输出空间中的贡献幅值、方向相关性和残差化差异。不同头的原始 V 坐标不可直接当同一语义空间比较。

**怎么比：**比较头间分歧、token 上分歧的集中位置，以及其在 V+/V−、A/B 中的分布。排除 softmax 温度、QK 尺度差异造成的简单解释。

**可能的操作：**优先把多头差异变成**token 级优先级**，让插件仍以 token 压缩为主。只有完整结构化实现能带来收益时再研究剪头；不把 head mask 清零称为加速。

#### P18｜重要位置或共享分组跨层能否持续

**取什么：**固定 token 来源坐标，追踪优先级排序的 Spearman、候选 top-set 的 Jaccard、相似度组的成员持续率；在没有压缩的 dense 路径上先测，再在压缩后映射原始成员追踪。

**怎么比：**正常与异常输入中，这些集合／分组能持续几层？稳定是否只来自静态背景、位置编码或同一相机？同时比较局部更新而不只 hidden state。

**可能的操作：**共享分组复用、压缩路由刷新频率、分阶段 token 配额。只在一个 clip 内复用的分组不称跨视频 KV cache。

## 4. 第一轮实际要运行哪些，不让 18 个探针拖垮进度

**一级筛查：**P01、P02、P04、P07、P10、P11、P13（适用时）、P16。一个共同只读采集器输出这些统计，不为每个探针重新解码视频。

**二级解释：**从一级稳定差异中最多选两条，加入 P05/P06/P08/P12/P17/P18 中最相关的探针。P03 需要正常参照校准，按价值决定是否加入。P15 类别复核始终跟随候选进行。

**三组最值得优先区分的现象：**

1. 差异是否存在于 token 分布尾部，而不是整体均值？对应局部处理优先级。
2. 差异是否存在于 token 之间的关系，而不是单 token 幅值？对应关系约束的合并。
3. 差异是否体现在跨时间／跨层的持续性？对应预算与路由刷新。

三者只是可观察问题，不是三个预设模块。主论文最终只需要一条清晰性质与一个主插件，第二模块必须对应独立且必要的证据。

## 5. 统计、图和输出格式

### 5.1 不把 token 数当独立样本数

clip 内先汇总，再以视频为重采样单位计算效应与置信区间。C2 先对每视频求 A−B，再做视频级配对 bootstrap。C3 若有匹配组，按匹配组重采样。建议初始 bootstrap 1000 次，记录 seed。

一级结果先描述分布、方向、效应量；若使用显著性检验，对预先登记的探针家族控制多重比较。筛选后在 confirm 固定方向和定义重新测，不在 confirm 上反复换公式。未发现差异也保留表格。

### 5.2 每条候选的四张图

1. **层×性质的正负效应图**：不是只放两张漂亮热图。
2. **原始分布和类别分层图**：显示重叠程度、样本数量与不确定性。
3. **时间曲线／空间图**：有时间真值时 A/B 标注；无真值时明确 V+、V−。
4. **同预算操作曲线**：候选信号引导的 token 处理 vs 随机／均匀／通用处理，报告任务指标及真实成本。

只存实际结果；图标题不得写预设方向。案例按固定规则抽取，成功、无效和反向案例均保留。

### 5.3 最少三种表

`cohort_index.jsonl`：

```json
{"video_id":"example_only","official_split":"train","partition":"fit","role":"explore","weak_label":1,"temporal_label":null,"label_source":"video_weak","source_frames":[10,12,14],"clip_start_s":0.4,"clip_end_s":1.4,"scene_group":null,"motion_bin":null,"category_for_analysis_only":null}
```

上例仅说明 schema，不是运行记录。

`probe_summary.csv` 至少包含：

```text
run_id, encoder_id, checkpoint_digest, video_id, clip_id, partition,
weak_label, temporal_label, label_source, layer_index, layer_depth_fraction,
site, sublayer_kind, head_id, probe_id, statistic_name, statistic_value,
num_valid_tokens, sampled_token_count, query_count, backend, dtype
```

`contrast_summary.csv` 至少包含：

```text
contrast_id, probe_id, encoder_id, depth, group_definition, stratum,
num_independent_videos, effect, ci_low, ci_high, test_name, adjusted_p,
selection_source, confirmation_source, status
```

标签和类别只在采集后 join 到分析表。线上 `reducer.forward()` 不接收这些字段；也不接收能泄露类别的文件路径、视频名字或未来层统计。

## 6. 从观察结果决定插件，而不是从插件寻找论据

| 实际观察到的性质 | 第一种最小操作 | 必须比较的相同预算对照 | 需要避免的跳跃 |
|---|---|---|---|
| 差异集中于局部尾部，主体高度共享 | 按该性质保留局部代表，其余组内合并 | 随机同数量代表、幅值／attention 基线 | 尾部一定是异常真值 |
| 正负差异主要在 token 关系而非单点数值 | 关系分组后合并，保留关系多样性 | 纯余弦合并、随机分组 | 图社区就是物体或异常区域 |
| 时间关系的持续性区分输入 | 稳定关系时间合并，变化关系保留更多代表 | 等预算空间合并、等间隔时间抽样 | 运动大就是异常 |
| 差异在某相对深度阶段形成 | 分阶段 token 配额与一次／两次压缩 | 相同插入位置的通用策略 | 仅仅推迟压缩就归因于新分数 |
| 多头协同对部分位置有稳定差异 | 由协同代理产生 token 级优先级 | 单头／头平均／随机头信号 | 观察到头差异就必须剪头 |
| CLS/pooled 汇聚在少数组上不同 | 读出相关代表选择／合并 | 通用显著性、同预算简单池化 | 把 pooled 叫 CLS 或动作置信度叫异常概率 |
| 未出现稳定正负差异，但压缩本身有效 | 报告通用压缩结果，继续其他性质或缩小任务特异主张 | 最强通用基线 | 编造异常特异性质 |

选定候选后先试单个 block 的操作，再决定是否渐进。最小操作验证关心“哪些计算可以共享并保持任务结果”，不是必须证明压缩损坏检测。

线上优先使用固定层预算＋输入自适应 token 身份，便于批处理。是否增加可变预算由 P09/P16 证据和真实吞吐决定，而不是因为“动态”听起来更先进。

## 7. 训练决策由信号识别难度决定

- 当前层便宜统计即可识别：规则型、无梯度插件。
- 正常原型或阈值足够：有数据校准、无梯度插件。
- 性质明确但昂贵探针无法部署：训练小预测器估计优先级／组关系／预算；昂贵探针离线产生监督，只使用合规开发数据。
- 不从一开始联合微调 encoder。训练小插件也可能需要后缀网络反传，不能用参数少推断激活开销低。

跨模型统一先要求同一输入统计定义、同一核心算法和同一预算口径；允许架构桥处理布局与位置。分别训练称“结构通用”；共享参数在未见模型上使用才称“跨 encoder 参数迁移”。

## 8. Codex 验收与停止分支

进入方法实现前，提交 `finding_card`，至少包含：

```text
研究问题；正常/异常分组；标签权限；探针精确定义；真实运行 ID；
差异方向和效应范围；混淆对照；独立确认；反例；
在线可用代理；候选 token 操作；代理开销；最近工作核对；
状态：observed / confirmed / actionable / deployable / rejected。
```

`confirmed` 不自动等于 `actionable`；统计差异须经过同预算操作验证。若差异反向、仅某类别成立、受场景控制后消失，更新卡片和主张，不改原始结果。最多并行两个候选操作，最后保留一个主插件，必要时加一个互补组件。

**第一轮交付：**一个真实 architecture receipt、8 段以上真实视频的探针健康检查、探索集的正常—异常分布图、至少两份包含对照和反例的候选卡、下一轮最小操作的明确配置。此时不要求论文题目或最终模块名。
