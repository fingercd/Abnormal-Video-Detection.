> 本文件设计写作工作区和结果到论文的路径，不是论文成稿，不包含虚构结果。
> 与 [02 重构说明](02_ENCODER_SCOPE_AND_REFACTOR.md) 共用唯一目录方案。没有额外的第七份交接文档；下列将来需要的工程文件由 Codex 在仓库实施时创建。

## 1. 这篇论文到底围绕什么写

论文不是介绍一个无关任务的通用 encoder bench，也不是先证明压缩有害再修复它。研究对象是：

**正常与异常视频在已选视频 ViT 中呈现怎样不同的 token 分布、关系或演化；这些差异怎样指导 token 的预算分配、保留、融合或交互缩减；同条件下能否保持检测质量并降低实际开销。**

可以先确定四个章节问题，不能提前填入答案：

1. 什么现象在正常—异常对照中出现？对照和独立确认排除了什么解释？
2. 现象发生在什么层、位置、交互或时间范围？需要哪些输入才能识别？
3. 根据它，哪些 token 应独立保留，哪些可以融合，预算怎样分配？
4. 一个统一插件在多个 encoder 和数据集上取得怎样的质量—效率权衡？

论文题目、方法名、摘要里的“发现”和百分比，在结果确认前保持未定。可以使用工作代号 `WSVAD-Token-Study`，不要让名字反过来迫使实验支持某个结论。

原始视频和完整 attention 不放在 `paper/`；图只导入经过审核的选定片段或统计。`releases/` 不意味着自动提交，只有作者授权才执行任何外部提交动作。

## 4. 从一个实验数字到论文的一条线

```text
数据 manifest / 权重 / 代码 / 环境 / 完整配置
                       ↓
               runs/<run_id>/
      探针统计、检测结果、性能结果、失败记录
                       ↓ 资格过滤与成对检查
              exports/<export_id>/
        正负对比分布、主表、消融、效率曲线
                       ↓ 可重复脚本
       tables/generated + figures/generated
                       ↓ claims.yaml / metrics.tex
                   main.tex
```

每个导出至少保存：源 run 列表、数据角色、协议 ID、实际 encoder/representation/sampling 身份、检测头训练条件、种子、预算定义、统计脚本摘要、导出日期。

对不完整数据集、没有通过 audit 的记录、没有真实 GPU 计时、仍开启分析 hook 的性能记录，导出器拒绝进入正式主表；可以进入明确标注的 diagnostic 表。

**禁止在 TeX 里手改一个 AUC 或加速比。**修正应从原始评测或统计脚本开始，生成新的 export，让所有图表和摘要中的数值同步变化。

新命令例如 `paper export`、`paper check` 只是待实现的入口名称；先写模块与测试，再在 runbook 标记可执行。不要给用户输出不存在命令的“成功日志”。

## 6. 观察章节应该放什么，而不是什么

观察章节主图优先回答：**正常与异常有什么不同、差异发生在哪、在控制混淆后是否仍成立。**

建议候选图如下，最终按数据只选最有解释力的 1–2 个，不要求全部塞入正文。

| 图 | 内容 | 需要防止的误读 |
|---|---|---|
| 正常—异常分布图 | 一个经确认性质在独立视频上的分布及效应量 | 不把每个 token 当独立样本，不只选最好案例 |
| 同视频事件内外曲线 | 真实异常事件、事件前后该性质随时间的变化 | 必须有可靠标注；不能用伪标签冒充事件边界 |
| 层×性质差异图 | 相对深度上的组间效应与置信区间 | 不是把不同维数模型的原始方差直接相减 |
| 同预算操作验证 | 性质驱动分组/预算与随机、通用策略的对比 | 证明不仅是“分布不同”，而是能支持压缩决策 |

若使用严格 W 协议，开发时只有视频标签，正文发现应先陈述为“来自异常视频的输入分布”。方法冻结后可在官方时间标注上做定位诊断，但不能伪装为先前独立的开发证据。

“异常 token”仅在有支持的空间证据时使用；否则写“异常片段中的高响应区域”“与异常视频标签相关的 token 统计”等更准确表达。

## 7. 方法章节怎么从性质自然长出来

为每个方法步骤写一个对应关系表，先给内部评审看：

| 方法步骤 | 依据哪个已确认性质 | 推理时可用信息 | 省掉什么计算 | 多加什么成本 | 对应消融 |
|---|---|---|---|---|---|
| 待定步骤 1 | finding ID | 当前层张量/冻结校准 | 待测 | 待测 | 同预算去掉性质信号 |
| 可选步骤 2 | finding ID | 待明确 | 待测 | 待测 | 去掉这一组件 |

如果一个步骤填不出独立的依据或消融，就先不加。一个主要策略加必要的结构桥已经可以形成完整方法；桥的 reshape 和位置维护通常属于正确实现，不单独包装成算法贡献。

方法描述必须明确：压缩发生在 Q/K/V 投影前后、attention 前后或 block 间；保留 token 数是每层还是最终；是否保留 CLS；怎样处理时间位置、合并质量、readout；训练/校准阶段需要什么标签。

最终叙述允许多种分支。例如异常—正常差异可能体现为少数 token 分布尾部、关系的变化、或深层全局读出的集中程度。只写真实验证的分支，不把所有候选性质并列当发现。

## 8. 实验章节与主表的最小充分内容

主表建议使用配对方法比较，按 encoder 分块。必要字段：数据集、head、插件训练/校准条件、预算定义、AUC/AP、相对 dense 差值、固定 batch 延迟、吞吐、峰值显存。

三个实验问题分别报告：

**直接插入。**同一 dense detector 固定，替换 encoder 的 token 路径。明确 checkpoint/feature 兼容契约；所有方法都不额外重训 head。

**允许后端适配。**每种压缩表示重新训练同一 head，使用相同配置选择和训练预算。这组不能和前一组混成一个胜出表。

**性质机制。**与相同 token 数、相同插入层、相同控制成本下的随机或无性质策略对比，说明真正起作用的信号是什么。

数据规模不够时，主 encoder 做完整预算曲线，其他三个做关键预算；不要为了每格都有数字复用无效或不兼容结果。第二检测头是补充，不强制四模型全部搭两头。

论文中的其他 WSVAD 方法可作为背景精度锚点，但 I3D、CLIP、多模态大模型、额外监督条件必须分栏。改变 backbone 本身带来的精度差异，不归入压缩插件收益。

## 9. 四页技术内容的建议分配

这是组织建议而非格式要求：引言与问题约 0.6 页；性质与关键图约 0.7 页；方法约 0.9 页；实验和消融约 1.6 页；结论与必要局限约 0.2 页。最终以可读性调整，不能靠极小字号塞内容。

优先把“正常—异常对照证据”“插件定义”“公平质量—效率结果”放进正文。大规模探针全集可以保留为可复现研究资产，不能把唯一支撑主张的证据藏到不确定是否允许的补充材料。

推荐正文最终保留：一张观察/结构图，一张 Pareto 曲线，一个跨 encoder 主表，一个紧凑消融表。没有图的真实数据来源之前，只做布局占位，不填示意性的实验数字。

## 10. 参考文献与最近工作的核查

`notes/related-work.md` 对每个最接近工作记录：准确题目、版本日期、原始来源、压缩对象、插入位置、训练监督、任务、已实现组件、尚未核对点。

本轮应优先核查的原始来源：

- ToMe：Token Merging: Your ViT But Faster，https://arxiv.org/abs/2210.09461 。通用 token merging 已有视频实验，不把“首次免训练视频合并”作为主张。
- vid-TLDR：https://arxiv.org/abs/2403.13347 。视频显著性/冗余压缩相关，是重要直接比较候选。
- STPrompt：https://arxiv.org/abs/2408.05905 。弱监督 VAD 的局部与时序提示相关，不把“异常具有局部性”独占为新发现。
- LAVIDA：https://arxiv.org/abs/2602.19248 。正常/异常叙述、MLLM 与视觉压缩相邻；其完整系统的监督和任务边界应与本论文区分，不能只看一个压缩组件就把全系统称为相同设置。

上述来源仅用于校对研究位置，不提供本论文的预设结论。其他候选论文按实际结果再检索，所有 BibTeX 核对题目、作者、年份和版本。不采用历史 ideas 中未经独立核实的 novelty matrix 或模拟审稿分数。

## 12. AI 辅助的边界与作者责任

当前大会投稿页允许将 LLM 用于构思辅助、代码/可视化和语言修改，但禁止把未经核查的内容、完全由 LLM 撰写的章节或重要稿件组成部分作为作者工作直接提交。作者需要真正完成并核查论文的论证与结果。

因此这里交付的是研究与工程指南，而不是可直接投稿的整篇论文。Codex 可以整理真实表格、定位数字不一致、检查引用、提供结构建议和修正代码；不要让它自动写完所有章节并替作者点击提交。

为 AI 辅助建立简短使用记录：做了什么、哪些输出被人工验证、是否需要按最新规定披露。不得把对话中建议的性质、计划值、合成样本或空结果当成实验观察。

## 13. 图表、隐私与案例清单

可视化保存真实视频 ID 的内部索引、时间戳、crop、token 坐标转换、模型层、压缩预算及候选选择规则。公开时按数据许可处理人物、隐私与敏感监控内容，避免为好看而展示不必要的可识别信息。

可视化中只画被真实保留/合并的 token；如画 attention，说明是何层何头、是否聚合、对哪些 key 做归一化。不能把近似时间映射画成精确异常框。

至少保留正常高响应、低运动异常、压缩后变化较大等边界案例。它们帮助界定方法，而不是必须出现在主图里的负面装饰。案例挑选规则在看到最终效果前登记或明确标为事后说明。

## 14. 交付与发布检查

论文 release 需要：方法冻结记录；所有主表对应的 audit 与完整结果；独立确认与必要方差；图表与摘要数值一致；引用可定位；数据/权重许可；作者审核；最新官方规则核验。

编译目录可反复清理，但仅限确定的 `paper/icassp2027/build/`，不能泛化为清理工作树。生成 release 时保存源码摘要和 export 锁；不要把本机绝对路径、服务器账户或密钥打包公开。

最终发布的复现入口优先支持 active 四个。旧 encoder 不必为本论文全部复现，但原有代码仍保留兼容。论文 claims 必须与真实已完成模型数量一致。

## 15. Codex 对本文件的验收

工作区创建后，应能从每一个论文指标追溯到一个合法 export，再追溯到源 run、数据与模型配置；源码中未完成的值不会被自动替换成模拟数字；inactive encoder 文件集合和内容摘要没有因写作整理发生变化。

首轮只创建论文骨架、requirements/claims 结构及数值导出测试。没有实际观察前，`02_observations.tex` 不写“我们发现”，`03_method.tex` 不预填最终算法，摘要不写未测量的提升。
