# 06｜实验口径、统计、性能、训练与论文主张的详细注意事项

> 适用对象：正常—异常性质驱动的多 ViT WSVAD token 压缩研究。
> 本文件是工程和实验约束，不预判任何插件一定提高精度或一定失败。目标是在明确的检测质量容忍度下，取得可验证的净加速与显存改善。
> 配套：[01 探针](01_NORMAL_ANOMALY_PROBES.md)、[02 架构](02_ENCODER_SCOPE_AND_REFACTOR.md)、[03 流程](03_EXECUTION_RUNBOOK.md)、[05 写作](05_ICASSP_PAPER_WORKSPACE.md)。

## 1. 先对齐研究中的四种“异常”

| 名称 | 依据 | 可以说什么 | 不能自动推出什么 |
|---|---|---|---|
| 异常视频 | 视频级正标签 | 该视频包含异常事件；可与正常视频做 bag 级分布比较 | 视频中每个 clip 都异常 |
| 异常片段/帧 | 可靠时间标注 | 某时间区间属于标注的异常事件 | 所有空间 patch 都是异常证据 |
| 候选异常相关 token | 与标签/事件或检测响应存在统计联系 | 某些 token 的性质与异常相关 | 已定位真实物体、因果或唯一证据 |
| 检测头高分 clip/token | 模型输出或代理分数 | 模型认为它更可疑 | 真实异常标签，或可以不加说明用于监督 |

用户要找的是异常输入相对于正常输入的性质，而不是先给 token 人工分出“重要/不重要”。实验中可把重要性操作化为预算分配优先级，但该优先级必须由可见张量与确认过的性质产生，不能由测试真值直接指定。

压缩目标也不等于“找到最像异常的 token 然后全部保留”：如果证据表明某些正常上下文关系对判别有用，它们同样可能需要预算。最终规则由受控实验决定，不预先要求仅保异常或仅压背景。

## 2. 数据权限：探索需要标签，不等于可以随便看官方测试

### 2.1 W：严格弱监督开发

fit/confirm/select 都从官方训练视频中按视频 ID 划出，算法训练与选择只使用视频级标签。正常统计原型只拟合 fit 正常视频。可比较 V+ 与 V− 的性质分布；不能把 V+ 中的片段命名为真异常片段。

最终冻结方法后，可以在官方测试时间标注上分析异常事件内外的性质，注明这是 post-freeze evaluation。若看完该分析又改层、阈值或插件，它已参与方法开发，不能再当独立确认。

### 2.2 D：有独立细粒度诊断开发集

需要研究真实事件发生时的局部性质，可使用与官方测试隔离的标注开发集。记录来源、数量、标注过程和权限。如果这些时间/空间标注影响了性质选择或方法设计，应披露“模型优化使用视频级标签，但开发诊断使用额外细粒度标注”，不能仅因损失函数没吃标注就称全流程严格弱监督。

在一周内，W 适合先完成；D 是可选、明确标注的研究分支，不为赶时间重新划官方测试然后仍报原 official 名字。

### 2.3 实际权限隔离

部署策略模块不导入 `research/labels.py`；训练与推理参数不含真实异常区间。敏感的诊断标注路径只给对应分析阶段。新增测试在替换视频文件名、类别目录名、ID 后确认 reducer 决策不变（像素与允许状态保持相同）。

正常参考库、阈值、协方差、PCA/SVD 基底、代表原型也属于拟合资产，必须有 fit 数据摘要。不能在整个测试集上先做分位数归一化再称单视频在线推理。

## 3. 样本选择和混淆：让差异确实与异常相关

只挑 3 个打架视频和 3 个安静走廊视频，观察到的差异可能来自场景、摄像机、运动、编码质量或人群。先用小样本调试，然后扩展独立视频与匹配控制。

对每个探索视频记录：来源、场景/拍摄方式、分辨率、帧率、时长、镜头运动或切换、近似运动层次、亮度、人群密度等可获得信息。未知填 unknown，不让 LLM 凭空标注。

最有价值的控制包括：高运动正常与高运动异常；低运动异常与低运动正常；同一异常视频事件前后；相近场景的正常视频。它们不是额外筛掉困难样本，而是检查同一性质是否在控制因素后仍有解释力。

完全匹配有时不可实现，应报告剩余差异。不要用异常标签决定 crop、抽帧密度或视频长度，再把输入差异当模型发现。

按来源视频或近重复组划分。一个视频的前半段在 fit、后半段在 confirm，不构成独立视频确认。与同一个源视频剪辑出来的不同文件也应尽量成组。

## 4. 中间统计最容易算错的地方

### 4.1 LayerNorm、特征维数与方差

如果要观察 norm、幅度或通道方差，记录是 LayerNorm 前还是后。LayerNorm 会强烈约束每个 token 的通道分布；不能只看归一化后的 norm 近似常数就宣布正常—异常没有差异。

按 token 的通道方差、按所有 token 的空间方差、按时间的轨迹方差是三个不同对象。每条指标写出 reduction 轴、归一化方法和 padding 排除规则。

跨模型的原始 norm/方差受到维数、层参数、位置处理和预训练影响。优先比较各模型内部的正常—异常效应，再比较方向与相对深度，不直接把两个骨干的数值拼起来当同一量纲。

### 4.2 谱和有效维数

说明特征是否中心化，使用 singular value 还是 covariance eigenvalue。有效秩若采用能量概率，应定义 `p_i = sigma_i^2 / sum_j sigma_j^2`；零能量输入标退化状态，不能产生 NaN 后静默丢弃。

采样 256 个 token 得到的秩受样本数上限约束，不能宣称是全视频真实 rank。正常和异常使用相同采样规则与预算；记录 sampling seed。谱可以作为观察，不要求在部署时重复昂贵 SVD。

### 4.3 Attention 行、列与均值

对一个有效 query，softmax attention 的 key 权重之和等于 1。在相同 key 数 N 下，全矩阵平均权重是 1/N；它不是区分正常与异常的有意义“平均注意力强度”。

应比较行熵/集中度、列接收质量分布、空间距离结构、时间范围、关系社区、head 贡献等。mask 使有效 key 数不同则必须按各 query 有效集合处理。

采样 query 行时仍对完整有效 key 集合归一化；只抽少量 key 后重新 softmax 得到的是另一个量，必须标作近似/子集统计，不能与完整熵混淆。归一化熵除以 `log(N_valid)` 时，N=1 单独处理。

### 4.4 Q/K/V 和输出贡献

使用实际参与 attention 的 Q/K：包括 Q/K norm、缩放、位置旋转/偏置和 mask，而不是仅截获线性层的原始输出后假定一致。

相似 K 不保证相似 V；相似 attention 不保证相似更新；不同 head 的 V 在不同投影子空间里，不适合直接用原始余弦当 head 功能相似。跨 head 比较时优先观察经对应输出投影进入公共 residual 空间的贡献。

对 pre-norm block 明确 `U_attn` 和 `U_mlp` 是加到 residual 上的分支输出；不要把 residual 本身的大数值掩盖分支变化。

### 4.5 CLS、class 和 pooled readout

真实 CLS token、动作分类 head、异常标签类别、adapter 最终 pooling 是四件事。没有 CLS 的模型不添加一个虚假的 CLS；没有 classifier 的模型不能用 random linear head 得到“类别分布发现”。

TimeSformer 是否有 CLS，以及当前 adapter 是否通过 CLS 读出，分别记录。某个动作 classifier 的熵变化只说明原生类别分布变化，不能直接当异常概率；相关结果作为辅助分析。

### 4.6 位置、padding 与来源

tubelet 往往覆盖多帧，不能按一个扁平 token 对一个原视频帧简单映射。空间 patch 的确切坐标要来自真实 patch embedding、flatten 顺序和 crop。

深层 token 的“来源位置”是计算索引/初始支持，不代表其语义只来自该局部区域；经过全局 attention 后尤其如此。可视化须说清楚。

排除 padding、重复填充帧、特殊 token 后再统计；需要保留的特殊 token 不进入普通 patch 的压缩预算分母，或显式统一分母定义。

## 5. 统计结论：按视频而不是按百万 token 计算置信度

一个视频内的 token、帧和窗口高度相关。先定义每视频的统计摘要或保留层级结构，再做正常—异常比较。置信区间可用视频级 bootstrap；同视频事件内外用配对差值和以视频为组的 bootstrap。

探索阶段允许扫描多层、多指标，但不能从几百个组合中挑一个很小 p 值作为最终证据。先冻结候选，再在独立 confirm 视频确认；多重检验范围和必要的 FDR 方法登记。

报告效应量、置信区间和分布重叠，不只报告 p 值。某性质只在一种异常类别成立也有价值，但主张范围应缩小，不能泛化成所有异常。

默认 1,000 次视频 bootstrap 是工程起点，不是普适统计最优值。明确随机种子和抽样单元；样本太少时不把窄置信区间当可靠证据。主指标 bootstrap 需要重组被抽视频的全部帧；退化到单一标签的重复样本应重新抽样并报告处理规则。

如果用 probe 统计预测视频标签，应采用独立视频验证，并和仅用场景/运动等简单 nuisance 特征的对照比较。probe 可分正负不等于它已经能指导 token 压缩，仍需要同预算操作实验。

## 6. 从发现到压缩，至少跨过三道门

**关联门：** 在正常—异常对比中存在可重复性质，或存在有意义的类别/时间条件差异。

**决策门：** 该性质能指导 token 优先级、分组、预算或插入层；相同 token 数与相同位置的控制实验有区别。不能只展示性质与标签的相关性。

**部署门：** 推理时能用便宜的当前信息实现该决策，算上额外开销后有净收益，检测质量达到事先定义的标准。

注意相反方向也可以有用：异常可能更集中，也可能更分散；关系可能更稳定，也可能更快速变化。只有证据决定某一分支是否值得实现。不用通过更改统计定义，把结果强行变成预期方向。

若没有稳健的正常—异常差异，但通用压缩效果好，可以如实保留通用结果；这不足以支持“异常特有机制”的论文主张。要么进一步研究适当的条件分层，要么缩小标题与贡献，不制造异常故事。

## 7. 主指标与“保持精度”的可操作定义

UCF-Crime 主报告 frame ROC-AUC；XD-Violence 主报告 frame AP。遵循数据集协议，在同一评测实现和时间覆盖下比较。主链已提供 micro frame ROC-AUC/AP；不能把每视频 AUC 平均与全帧拼接 AUC 混称同一指标。

普通 accuracy 容易受正常帧占比影响，不作为主要质量结论。F1、precision、recall 需要说明阈值来源；不能只报测试集搜索出的最佳 F1。可在允许的 select 数据上固定阈值，或在正常验证视频上按预设误报目标定阈值，再报告测试实际误报。

建议把“保持质量”写成可事先审核的非劣性标准：

```text
Delta = metric_compressed - metric_dense
可接受条件 = 预先约定的 Delta 下界不低于 -delta_quality
```

`delta_quality` 由作者在看正式测试前选定并记录，最好结合 dense 多 seed 波动和任务容忍度。比如 0.5 个百分点只能作为讨论用的工程选项，不是本文件保证或规定的通用阈值。用户若要求完全不下降，也需要区分点估计相等与不确定区间，而不是把微小噪声当严格证明。

同时报告点估计差值、paired video bootstrap 区间和独立 head 种子变化。Bootstrap 衡量测试样本不确定性，head seeds 衡量训练随机性，二者不是同一种方差。

不能通过全视频分数都向正常缩小而得到“分数一致、模型没坏”的假象；主指标、正常误报和短异常表现共同检查。异常视频子集上的 AUC 只作额外指标，并说明子集是否仍同时含正常/异常帧。

## 8. 公平比较：哪些必须完全一样

对同一个 encoder，dense 与各压缩方法应匹配：checkpoint、预处理、输入帧数/分辨率、采样坐标、crop 数、视频时间覆盖、pooled readout、head、精度与 backend。方法只在明确允许的 token 操作与适配步骤上不同。

预算至少有三种，不能混称：最终保留 token 比例、逐层 token 轨迹、实际计算/延迟预算。相同最终 token 数但插入层不同，计算量并不相同；比较时给出匹配层对照和真实预算曲线。

随机/均匀 baseline 应保留相同数量特殊 token，使用相同合法布局约束。不要让自己的方法有每帧最低保留数，而随机基线可以删空整帧，随后把结构崩溃当优越性。

所有方法获得相近的调参预算。若 baseline 采用官方默认而 ours 做大量搜索，需要披露并补合理的基线调优。重要消融是“同样保留数量，去掉性质信息”，不是直接减少模块并顺便改变 token 数。

跨 encoder 可以沿用各自原生输入 profile；这种主表用于验证同一插件在各模型内部的收益，不用于断言某 encoder 绝对更优。要做绝对骨干排名，另设公平的时间覆盖、输入/训练与计算协议。

## 9. direct_insert、refit_head 与参数通用性

`direct_insert`：同一 dense head 冻结，压缩方法插入 encoder。所有基线同样不重训。它检验即插即用兼容性。

`refit_head`：冻结各自的 encoder+reducer 表示，分别训练相同检测头。所有方法使用相同选择规则与预算。它检验允许后端适配后的性能，不得混入 direct_insert 的主张。

插件训练方式清楚区分：

| 方式 | 正确描述 |
|---|---|
| 固定规则，不拟合数据 | 无额外插件训练；满足条件时可称无需校准 |
| 正常训练集原型、分位数、SVD 等 | 无梯度训练但有数据校准 |
| 学习少量阈值/线性或 MLP 路由 | 轻量可训练插件 |
| 每个骨干单独训练同结构插件 | 方法结构通用，参数需适配 |
| 在部分骨干训练，在未见骨干不改参数 | 参数跨骨干迁移；需独立验证 |

整个 WSVAD 系统仍可能训练 MIL head，所以“插件免训练”不等于“整个系统零训练”。数学公式与是否训练无关，拟合协方差也是数据适配。

训练内部插件时检查梯度真实流到参数、dense encoder 是否按设计冻结、soft/hard 路由训练推理是否一致。当前 V-JEPA 2 wrapper 的 `no_grad` 是需要处理的明确边界。先用最小梯度测试确认，而不是只看 loss 在下降。

## 10. 指纹与缓存：不能为兼容实验伪造身份

现有抽取身份包含 encoder、sampler、streaming，预测还检查 checkpoint 对应 fingerprint。这种严格性应保留；论文流程新增兼容许可，而不是把校验删除。

至少分开：

- backbone identity：权重、实际预处理、结构、readout；
- representation identity：backbone + reducer 代码/参数/校准 + 插入位置/预算；
- sampling identity：train 和 evaluation 各自的真实抽帧/时间覆盖；
- head identity：训练的 representation、训练 sampling、loss、seed、checkpoint。

训练 32 段、测试 dense 必须是预先批准的评测协议变化；同一评测的 dense/compressed 仍完全匹配 test sampling。直接插入允许 representation 在 reducer 维度改变，不能顺便改 backbone、readout 或其他未知字段。

每次允许的兼容检查输出明确回执，保留源与目标身份、理由和差异字段。新协议不改变旧 CLI 的默认拒绝行为。不能通过覆写 feature-index 的 hash 让它看起来属于 dense encoder。

共享缓存时按 encoder/method/budget/calibration/split/sampling 隔离；先验证完整写入再标 completed，避免读取部分文件。并发抽取按 shard 输出，不能无锁更新同一 JSONL index。

## 11. 时间覆盖和数据集协议

UCF 当前固定训练 1,610、测试 290 的视频级官方划分，时间标注转成内部零起点半开区间。导入和转换以当前代码与固定来源为准，不凭文件名猜标签。

32 段中心 clip 再把预测扩展到整段，是一种稀疏评测采样口径；完整覆盖检查通过并不代表模型真正看过所有帧。正式比较要明确这种口径。新增 dense 固定 clip sampler 时，真实 overlap 的 clip 分数先聚合到帧，再形成合法、不重叠、无缺口的预测区间。

不同数据集的端点、帧率、索引和异常区间规则分别核实，不能把 UCF 的 1-based 转换照搬 XD。可变帧率视频同时保留解码 frame index 与时间戳，不只用 `round(t*fps)` 近似代替所有情况。

训练不足长度 clip 的 padding 不应作为额外异常证据；预测区间回填应遵循原始时长和有效帧 mask。不可用 `allow-incomplete-coverage` 掩盖丢帧或越界。

XD 主实验标为 RGB-only；若加入音频，另设模态对照且重新计算成本。ShanghaiTech 弱监督划分是可选，发布准确 ID 列表，不能与原 normal-only 设置混称同协议。

## 12. 真实加速：先明确省掉的计算在哪里

token 数减少不直接等于延迟同比下降。需要记录每个压缩位置前后的 `N_l`、实际 attention 的 query/key 长度、MLP 处理长度和重排成本。

以下都不是 encoder 压缩的充分证据：把 token 清零但 shape 不变；模型算完后删除输出；完整 attention 先生成再丢弃；压缩器内部 dense 计算比省下的更多；为了凑原网格又完全恢复原序列并执行所有后续算子。

只压 K/V 时 query 数和 MLP 计算可能没变，应测实际受益部分。只共享 MLP 更新也可以研究，但若最终文章声称 token 数降低，需要确实相应缩短部署序列。

同样，token 压缩通常不减少 backbone 参数量，最终 pooled feature 维数也可能不变。权重存储和磁盘 feature cache 是否减少分别实测，不从中间 token 数推断。

## 13. 三种计时层级与显存指标

| 层级 | 输入起点与终点 | 用途 |
|---|---|---|
| 模型层 | 已在 GPU 上、已完成预处理的张量 → encoder+reducer 输出 | 定位模型计算收益 |
| Adapter 层 | 与现有 benchmark 一致的 ClipBatch → 规范输出 | 比较实际接入成本；包含 adapter 内部预处理 |
| 视频端到端 | 约定的原始视频读取/解码 → 逐帧异常分数 | 说明系统部署收益，写清是否包括磁盘冷读和模型加载 |

现有 benchmark 模型加载在 repeat 前，不能称含启动时间。适配器总耗时已包含原生压缩时，不要把其子项再次加到总耗时。

正式计时关闭观察 hook 和昂贵统计。使用同步的 CUDA event 或正确同步的墙钟；预热和重复次数固定并根据方差检查。20 次预热、100 次重复可作为初始配置，不是必须值。报告 median、p95、样本量和输入组成，不只挑最短一次。

分别报 batch=1 延迟、相同固定 batch 吞吐、以及可选最大可容纳 batch。固定 batch 和“ours 可以开更大 batch”的收益分开。FPS 说明是采样帧/秒、clip/秒还是原视频秒/秒，禁止用标签回填帧数冒充实际处理帧数。

显存至少分：峰值 allocated、峰值 reserved、统计范围及 baseline 起点。保持模型/输入驻留方式一致；卸载不参与部署的教师与其他模型，再测部署峰值。不要 dense 留着教师、compressed 卸载教师。

晚层压缩不一定降低已在前层出现的峰值；模型参数、输入和缓存也可能占主要份额。测不到明显峰值收益就如实报告，不用某一层临时张量大小替代峰值。

四张或六张卡可以平行跑独立实验，但正式计时那张卡保持独占；记录 A100 型号、容量、MIG 状态（若有）、软件栈和是否有其他进程。不要改动用户现有系统权限或绕过服务器 GPU 使用保护。

## 14. 注意力 backend、精度和分析模式

PyTorch SDPA 的具体 kernel 与输入形状、dtype、设备等条件有关。分析时显式返回完整 attention 可能改变融合路径。dense 与 compressed 都应在各自可支持的同条件正式路径计时，并记录实际 backend；分析结果另存，不混入性能表。

使用 FP32 统计关键量可以减少舍入问题；部署精度与完整 baseline 一致，不能将 dense FP32 对 compressed BF16 的全部收益归于压缩。若 adapter 默认转换为 float，应核对真实 forward dtype，而不是只看配置字符串。

编译或动态 shape 优化采用对称的比较预算，首次编译/首次加载成本另列。为了可变 token 而禁用某个融合算子的代价要算入插件，不能只报估算 FLOPs。

对分析 collector 的 parity 检查：同输入、同 seed、eval 模式，hook 开关不改变模型输出；如显式 attention 与融合路径有正常浮点差异，应设定与 dtype 相符的容忍度并记录，而非要求所有路径逐 bit 相等。

## 15. 合并、位置和质量：正确性检查而非预定新方法

保留 token 的特殊标记和初始坐标；合并组记录代表、支持范围与质量。若所有组的质量之和不等于输入有效 token 数，首先检查重复选取、丢失或 padding 计入。

对于单次 attention，如果一组 key 对所有 query 具有相同有效 logits 条件，且 mask/位置偏置一致，可以用平均 value 和该组数量的质量补偿保持它们的合计读出。这是局部代数条件，不等于后续所有非线性 block 都无损，也不是可直接声称的新定理。

实际模型含位置相关偏置、Q/K norm、RoPE 或结构化时空 reshape 时，合并规则要验证这些条件，不能盲目加入 `log(group_size)` 就称完全保真。

TimeSformer 要验证不同帧间共享空间选择是否满足真实 reshape；变长 patch 数不代表可以任意产生不规则网格。bridge 不支持某项操作时立即报错。不要静默补零恢复整网格再把输出 token 数作为省算证明。

## 16. 两套结果都要保留：性质结果与任务结果

性质结果回答“正负输入有什么不同”；压缩结果回答“利用它是否有价值”。只看一个结果会误导。

性质图包含 clip/video 数、类别组成、采样和归一化方法、观察层和置信区间。任务图包含 baseline、预算、head 条件、实际成本及独立确认。

弱标签检测头可能利用场景捷径。使用其分数评价 token 贡献时注明这是模型判决相关证据；与真实事件对齐的结论需要独立标注检验，不因分数下降就声称因果必要性。

如果某个性质在异常类别间方向不同，可以研究类别无关的局部适配规则；但部署时不能先读真实异常类别再选择压缩策略。类别分析应先帮助界定范围，而不是产生隐藏的 oracle 路由。

## 17. 代码重构时最容易破坏什么

当前已跑通的模型、权重路径、上游锁、环境是高价值资产。先建立保护清单，再添加论文入口，不先进行大规模搬家。

特别注意：`compression.py` 与新包命名；`resources.py` 与 wheel 资源打包；旧配置没有隐式继承；原数据/帧级评测门禁；现有 fingerprint 匹配；`TemporalSupervisedHead` 的强监督语义；V-JEPA 2 `no_grad`；近似 token timeline 的解释边界。

选择性修复必须有实际测试。静态看见一个潜在池化分支问题，不意味着当前 native output 一定触发；先记录真实返回类型与 shape，再修改。baseline 也要在修复后的相同代码下重跑，不能把修复收益算作插件收益。

文件保护检查不仅看 `git diff`，因为用户有未提交文件；记录本轮开始时的实际内容摘要。禁止用 reset/clean 回到历史 HEAD。新目录可大改，未选 encoder 不改，共享路径兼容性由测试证明。

## 18. 风险与处理优先级

| 现象 | 首先检查 | 处理 |
|---|---|---|
| 正负差异非常大 | 采样、场景、数据来源、归一化、label 泄漏 | 加匹配控制，不急着命名发现 |
| 差异只在一条视频出现 | 独立样本量、镜头切换、损坏帧 | 扩展样本并记录反例 |
| 很多层 attention 平均值相同 | softmax 恒等式、N、mask | 换成分布/结构统计 |
| 插件“训练”但参数无梯度 | no_grad、detach、离散 selector、optimizer 参数 | 最小梯度测试，避免无效长跑 |
| token 减半但没有更快 | 匹配/排序/恢复、fused backend、MLP shape | 做算子分解，简化规则 |
| 只在重训 head 后有效 | 表示分布变化、head 兼容 | 正确归类为 refit，不冒充免适配 |
| 正常误报变少但异常召回下降 | 分数整体收缩、阈值口径 | 看 AUC/AP 与固定阈值分解 |
| 三个 encoder 中只有一个有效 | 特定预训练或结构条件 | 缩小主张，检查 bridge；不要伪造普适性 |
| 特征可读但 predict 指纹失败 | sampling 与 reducer 身份混在一起 | 使用显式兼容协议，不改 hash 糊弄 |
| 官方评测失败 | 视频集合、端点、覆盖、audit | 修正数据/预测，不降级 generic 当 official |

这些检查是为了保住可解释的积极结果，不是要求先证明压缩有害。范围可以收敛，证据不能省略。
