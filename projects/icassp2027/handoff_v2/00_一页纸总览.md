# 一页纸总览（事实版，不含倾向性结论）

> 本文件只列**可核对的事实**与**论文草稿和实测之间的落差**，供外部顾问独立判断。所有数字可在 `02_实验结果/` 中复现。

## 1. 实验是什么

| 项 | 内容 |
|---|---|
| 任务 | 弱监督视频异常检测（WSVAD）的**推理期 token 压缩** |
| 检测器 | UR-DMU（MIL，200 temporal bins，每 step 64 normal + 64 anomalous bags，3000 steps，固定最终 step，无按测试指标选 checkpoint） |
| 接入方式 | `direct_insert`：压缩特征直接接入已训练固定的 dense head，**不重训 head** |
| 编码器 | VideoMAEv2-B、VideoMAE-B、TimeSformer-B（三套独立 dense head） |
| 数据集 | UCF-Crime（1610 train / **290** sealed test，指标 frame ROC-AUC）；XD-Violence（**3950** accepted train / **800** sealed test，主指标梯形 PR-AUC，step AP 单列） |
| 规模 | 3 编码器 × 2 数据集 × 3 压缩方法 = **18 个压缩 run** + **6 个 dense 基线** |
| 预算 | keep_ratio = **0.60**（只有这一档） |

## 2. 三种压缩方法（代码见 `03_压缩方法代码/token_reduction/`）

**共同骨架（三者完全一致）**：插入深度 = 原生 block 数的 `ceil(0.5×N)−1`（实测 `depth=5`）；连续 **10** 个预算槽为一组，每组保留 `round_half_up(0.6×10) = 6` 槽；特殊 token 单独保留不计预算；预算单位 V2/VMA 是原生 patch token、TS 是**完整空间轨迹**。

| 方法 | 静态/动态 | 推理期选择开销 | 选哪些 token |
|---|---|---|---|
| `group_uniform`（对照） | 静态 | **零** | 每组取**原生顺序的前 6 个** |
| `group_random`（对照） | 静态 | **零** | 每组 **seed=0** 随机抽 6（一次性 mask，推理期不再随机，单 seed） |
| `pair_select`（主方法） | **逐前向动态** | **有**（算 L2 范数 + 排序） | 信号 = 每个相邻 pair 两成员的 **L2 范数取大者**；先按 pair 信号降序填 5 个"优成员"，剩余配额给最强 pair 的"劣成员" |

`same_budget_for_all_controls = true` —— 三者预算与配额表完全相同，质量差异只可能来自"选哪些 token"。

## 3. 压缩比（实测，来自 FeatureStore 真实执行形状）

| 编码器 | 原生 token/clip | 保留 | 名义 keep_ratio | **实测保留比** |
|---|---:|---:|---:|---:|
| VideoMAEv2 | 1568 | 941 | 0.60 | **0.6001** |
| VideoMAE | 1568 | 941 | 0.60 | **0.6001** |
| TimeSformer | 1569 | 897 | 0.60 | **0.5717**（轨迹粒度取整，比名义更激进） |

同一编码器内三方法保留比完全一致 → 跨方法预算严格匹配。

## 4. 质量结果（已解封，可核对）

**UCF-Crime / frame ROC-AUC**（0–100 标度，括号为相对本格 dense 的百分点）

| 编码器 | Dense | pair_select | group_uniform | group_random |
|---|---:|---|---|---|
| VideoMAEv2 | 80.63 | 81.02 (+0.39) | 80.53 (−0.11) | 81.17 (+0.54) |
| VideoMAE | 80.55 | 80.39 (−0.16) | 80.12 (−0.43) | 80.46 (−0.09) |
| TimeSformer | 78.68 | 78.68 (−0.00) | 78.35 (−0.33) | 78.89 (+0.21) |

**XD-Violence / frame PR-AUC（梯形）**

| 编码器 | Dense | pair_select | group_uniform | group_random |
|---|---:|---|---|---|
| VideoMAEv2 | 76.18 | 76.51 (+0.32) | 75.77 (−0.41) | 75.76 (−0.43) |
| VideoMAE | 70.34 | 70.94 (+0.61) | 71.48 (+1.14) | 71.42 (+1.09) |
| TimeSformer | 76.69 | 77.37 (+0.68) | 76.79 (+0.10) | 76.58 (−0.11) |

- **18/18 格全部通过 0.5 pp 非劣性边际**（10,000 次视频级 paired bootstrap，按视频弱标签分层）。
- 单方法 CI 半宽 **0.25–1.42 pp**。
- **方法间点估计差 ≤ 0.51 pp**：pair_select 在 UCF 上平均**不如** group_random（−0.15 pp，三个编码器全负）；在 XD 上平均优于两个对照（+0.26 / +0.35 pp），但在 VideoMAE×XD 上同时输给两个对照。
- **方法-vs-方法的配对 bootstrap CI 尚未计算**（当前不声称任何统计显著性或优越性）。

## 5. 效率现状

- 本轮**没有**可用的效率证据。GPU monitor 只覆盖约 3 分钟；FeatureStore 的 `plugin_overhead_ms` 是随 chunk 重算的滑动平均（早期值被初始化污染），且 `pair_select` 记 `transform_ms`、两个对照记 `gather_ms`，走不同代码路径，**不可用于任何效率主张**。
- 机制层面可确定的是：两个静态对照推理期**零**选择开销；`pair_select` 有逐前向选择器成本。定量数字待阶段 D 小样本 benchmark（协议见 `05_核验与审计/efficiency_protocol.md`）。

## 6. 可信度保证（可引用为方法学贡献）

- 18/18 extraction 合同通过**逐视频闭合核验**（视频 ID 集合精确一致、每视频 clip 数与 dense 目标逐一相等、0 缺口、clip 总数 = dense 记录总数）。
- 18/18 预测 `completed`、`official_frame_scores_read=false`、唯一视频数 290/800、chunk receipt 完整、无重复 clip。
- 检查点固定最终 step 3000；上游 UR-DMU 的按测试 AP 存最佳逻辑从未被加载；下游加载侧强制拒绝非固定 step。
- `official_frame` 帧覆盖恰为 `[0, num_frames)`，未覆盖帧直接报错，无插值 / padding / 静默截断。
- 装配器 fail-closed；其 stdout 只输出 status/cells/output，**不含任何指标数值**。
- 失败目录全部保留未覆盖；node2 未接入；一次提前读分事件（仅 1 个 dense 基线值）已如实记录。

## 8. 可以诚实主张的方向（供参考，不是结论）

- 在 0.60 预算下，推理期 token 减少对冻结 WSVAD 检测器**近乎无损**，且在 3 编码器 × 2 数据集 × 18 格上一致通过非劣性。
- 更强的一条：**"保留哪些 token"在该预算下不重要**——基于信号的选择不优于随机下采样。这构成一个经验边界（a smarter selector 的上界就这么低）。
- 严格的审计链路本身（逐视频闭合、固定 step、fail-closed 装配、paired bootstrap）是可引用的方法学贡献。
