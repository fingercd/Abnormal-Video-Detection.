## 1. 结论与本轮目标

下一轮以历史论文中的强检测基线 **CLIP ViT-B/16 + DSANet** 为对象，复现上一轮 VideoMAEv2 的完整三方法压缩矩阵：Attention Top-K、VisionZip 本轮适配版、uniform；插入 block 6/9/12，移除 50%/70% patch tokens，分别完成 UCF-Crime 与 XD-Violence 的提取、固定权重预测和配对质量评测。

正式质量矩阵共 **38 项 = 2 项 dense + 36 项压缩配置**。另安排有界的训练侧实现检查和短独占效率测量；它们单独计数，不混入 38 项完成率。

要回答的问题是：

1. 三种规则迁移到 CLIP 的图像 patch tokens 后，检测质量是否保持？
2. 内容相关选择/合并与固定均匀选择的行为是否不同？现有逐配置对 dense 的 CI 不直接证明方法之间有显著差异。
3. 包含选择、合并及信号取得开销后，是否真正降低 CLIP 编码器延迟和显存？
4. 编码器收益能否传递到原视频→DSANet 分数的完整流程，而不是被解码、crop 或检测头成本抵消？

本轮不以正式测试分数选层、选比例、改方法、切分支或挑 checkpoint。完整矩阵在首次正式测试前冻结，不只运行上一轮分数较好的第 9 层。

## 4. 冻结的压缩矩阵

### 4.1 38 项任务定义

| 方法 | 插入 block | patch 移除比例 | 数据集 | 正式任务数 |
|---|---|---|---|---:|
| Dense / identity | 不压缩 | 0% | UCF、XD | 2 |
| Attention Top-K | 6、9、12 | 50%、70% | UCF、XD | 12 |
| VisionZip 本轮适配 | 6、9、12 | 50%、70% | UCF、XD | 12 |
| uniform | 6、9、12 | 50%、70% | UCF、XD | 12 |
| **合计** | | | | **38** |

block 按 1 开始编号；代码 `block_index` 分别为 5/8/11。每个任务使用独立输出根和唯一 task ID，建议形式为 `ucf_crime-attention_topk-b06-remove50`。名字只是计划命名，不表示对应运行已存在。

### 4.2 位置、CLS 与真实长度

每个配置只在一个指定 block 做一次干预：**原生 attention 残差之后、该 block 的第二个 LayerNorm/MLP 之前**。不在每一层连续累积删 token，也不在 encoder 完成后才删特征。

224×224 的 CLIP ViT-B/16 预期为 196 个 patch tokens + 1 个 CLS；执行时以真实加载模型核验为准。

| 档位 | keep_ratio | 保留 patch 数 | 包含 CLS 的序列长度 |
|---|---:|---:|---:|
| Dense | 1.0 | 196 | 197 |
| 移除 50% | 0.5 | 98 | 99 |
| 移除 70% | 0.3 | 59 | 60 |

预算采用上一轮的 nearest-half-up 规则。CLS 始终保留在原位置，不参与 patch 预算，不被合并、重加权或重新初始化。位置 embedding 在原生入口加入；干预后保持来源顺序与索引，不重新插值位置，不新增位置编码。

### 4.3 三方法规则及信号口径

- **Attention Top-K：** 用当前 block 的接收 attention 重要性选择 patch，保留预算内 top-k，其他 patch 直接丢弃；排序和来源顺序沿用已实现规则。
- **VisionZip：** 沿用现有 dominant/contextual **4:1 输出分配**、native key 的多头均值余弦关系、contextual 代表选择与合并规则。合并对象仅限 patch；不通过 test 改分配比例、相似度阈值或 readout。称“本轮视频适配版”，不冒称原始完整 VisionZip 系统。
- **uniform：** 沿用原生 patch 序列上的均匀索引规则（当前实现为 linspace + round），不使用 attention、key 相似性或标签；不偷换为新的二维棋盘或随机采样对照。

计划采用 **patch 接收分数在 patch query 与 heads 上平均**，CLS 的 query/key 不进入 patch selector 的分数归一化、匹配或合并。这是为 CLIP 明确新增的 CLS 边界约定；必须在训练侧实现检查后写入协议并冻结，不能静默套用混入 CLS 的另一口径。原生完整 attention 计算仍包含 CLS，保持模型原逻辑。

CLIP 的原生多头 attention 可能使用融合实现，不能假设可直接 hook 到 softmax。若需要额外取得 Q/K 或计算选择信号，必须来自同一原生 LayerNorm 输入和权重，保持原 attention 输出路径不变，并把额外投影、attention 分数计算及存储成本计入插件开销。不能为了方便拿权重切换 attention backend 后，把 backend 差异算成压缩收益。实现不可核实时显式报不支持。

### 4.4 第 12 层是必要的结构对照

CLIP 最终采用 CLS → `ln_post` → projection 读出。若第 12 层 attention 已完成，之后仅修改 patch、不修改 CLS，且没有后续跨 token block，**patch 的选择/合并原则上不再改变最终 CLS 的语义**。因此该位置可能出现接近或等同 dense 的检测输出，这是结构上的预期，不能据此证明 selector 更好。

第 12 层仍可能节省部分 patch MLP 计算，但没有后续 Transformer block 可省；选择/合并开销可能抵消收益。要同时报告它的真实 shape、CLS 输出差值和净计时。不同 GEMM shape 可能带来浮点差异，训练侧记录实际数值误差，不能事后根据 test 分数放宽容差。

### P1：CLIP 桥与三方法接入

在现有 DSANet 工作流上增量增加 method、block、0.5/0.3 预算和单 task 质量入口。保留旧 PairSelect/0.8/0.6/0.4 模式原有身份，不把它改名成三方法结果。桥负责 CLS/布局/attention/readout，策略负责同一选择/合并规则。

1. identity/ratio=1 与 native 输出一致；不干预 CLS/位置/readout，attention 原路径不变。

4. 三方法各一份 feature 能被固定 DSANet 消费，两个数据集对应 head 与采样身份正确。
5. 第 12 层 CLS 行为符合结构预期；记录浮点误差，不以 test 质量反向确定容差。

## 8. 指标与统计协议

| 指标 | 本轮口径 |
|---|---|
| UCF 主指标 | frame ROC-AUC |
| XD 主指标 | 沿用 DSANet 已核验协议的 **非插值 step AP** |
| XD 补充指标 | 同时输出作者梯形 PR-AUC，明确其定义，与 step AP 分列 |
| 原生定位 | 复用原五个 tIoU 阈值的定位 mAP，单独列示 |
| 另一评分分支 | 原样导出为补充；不替代冻结 coarse 主分支 |
| 差值 | method − 本轮 dense |
| CI | 10,000 次视频级配对、按视频弱标签分层 bootstrap；seed=0 |
| 独立单位 | 视频，不把百万 patch 当百万独立样本 |
| 非劣容忍度 | 主指标 0.005，即 0.5 个百分点 |
| F1/阈值 | 没有独立冻结验证阈值则不新增该指标，不在 test 上调阈值 |

判定必须区分：

- CI 下界 ≥ −0.5pp：支持非劣。
- CI 上界 < −0.5pp：确认劣于非劣界限。
- CI 跨 −0.5pp：非劣证据不足。
- CI 全高于 0：支持当前配置/权重身份下提升；全低于 0：支持下降。
- “支持下降”和“确认下降超过容忍度”不是同一结论。

所有主指标在完整测试覆盖及时间轴映射核验后计算。XD raw→canonical 的映射沿用对应 DSANet 协议；不把 UCF/XD 或两轮模型的行数、帧数和指标定义混合。

逐配置 CI 未进行多配置校正，发布权重仅一个身份；报告不能称多 seed 泛化、不能按最高点估计选最终方法。若后续论文需要方法间显著性或多 seed 复现，再另立有界补充计划，不混入本轮预设结果。

## 9. 效率测量预算与验收

### 9.1 两层测量，不能互相替代

| 层级 | 起止边界 | 固定安排 |
|---|---|---|
| CLIP encoder | 已准备好的 GPU 图像 → 原生 pooled/CLS 视觉输出 | dense + 18 配置；batch 1 与 32；FP32/TF32 off；同设备/同输入/同 crop |
| 原视频完整流程 | 打开原视频 → crop/CLIP → 固定 DSANet → 实际分数回传 CPU | 两数据集各固定 16 个完整训练视频；dense + 18 配置；同原始视频与时间覆盖 |

计划编码器每配置 20 次预热、40 次同步测量，3 次独立重复、交错顺序；19×2×3=114 个计时组。若固定 batch32 不适配真实内存，先在训练侧确定所有配置共同可用 batch，并在正式计时前冻结，不能不同方法用不同batch后混成同一倍率。

完整流程每数据集 19×3=57 个计时组，合计114组，每组16个固定视频。该预算是有界的效率子任务，不是 head 训练，也不计入38项质量任务。固定暖缓存或冷缓存策略，方法间一致；记录解码/预处理、传输、encoder、DSANet及回传边界。

报告 median/p50、p95、吞吐、peak allocated/reserved、各层token长度、插件耗时与三次重复分布。可测性能保留全部原始样本；能耗、完整模型 FLOPs 没有可靠实测覆盖时保持未测/部分，不编造。

### 9.2 资源与停止条件

正式效率要求短独占GPU时间窗，不能与其他项目共享同卡计时，也不能擅自停止他人任务换取独占。先在已授权资源内等待/预约合适窗口；不能得到独占条件时交付“质量完成、效率待执行”的部分回执，并向用户说明具体资源缺口。

不因效率不理想删结果：延迟不降、显存不降或端到端不加速都是真实结果。上一轮DSANet已有“encoder batch32加速、完整视频收益不显著”的反例，必须保留这类边界，不能只报encoder最好倍率。

本计划把正式效率纳入最终交付；若因资源阻塞尚未完成，不把整个未来 goal 标为完成。是否改为仅质量交付由用户明确决定。

## 10. 生产调度与故障恢复

默认执行节点为node3，GPU0/1/2/3，每卡最多一个本项目任务。执行前只读核对实际PID、owner、完整命令、UUID、显存余量和CPU/存储负载；GPU号必须按UUID/queue实际slot报告，不按任务显示顺序猜。

有共享空余显存授权时，以现场验证的窄身份名单和显存限额调度。其他项目换代时重新核验，不永久放行未知PID、不反复盲重试。模型batch/allocator是执行条件，要冻结并记录；不能按test分数调整。

优先复用已有有界解码/CPU worker流水线，CLIP主线程负责模型/CUDA/写入。VideoMAEv2的r05执行配置不得直接标为CLIP已通过；任何新执行优化必须先证明输出/采样不变，再使用，且不把工程管线提速当压缩方法提速。

恢复分三类：

1. **连接/在线记录中断：** 先查原PID和原输出，再接回原SwanLab身份；不重新启动计算。
2. **启动前被保护门拒绝：** 核对确实无新计算PID，保留失败attempt，修复已知资源身份后再起独立attempt。
3. **真实计算失败：** 保留日志与partial，定位问题后仅在同身份/有明确恢复语义时续跑，不能覆盖旧失败目录冒充成功。

退出时`/proc`、`ps`、命令行的竞态按上一轮已定位经验处理；未知活PID仍拒绝。先创建本任务日志再后台启动，避免tail抢在文件创建前漏收CPU结果。

所有实验先建立SwanLab online run，再启动计算；结束回读状态与完成摘要。网络上传失败保留本地日志并补传，不能只凭本地文件说云端完成。
