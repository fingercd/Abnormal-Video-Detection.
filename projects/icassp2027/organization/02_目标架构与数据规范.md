## 中等解耦的代码边界

保留当前 `vadbench` 包与通用数据、encoder、训练/推理/评测主链。把论文已经实现的能力按**是否依赖 ICASSP 协议**分配到以下三层，不为目录整洁重复造训练或评测框架。

```text
src/vadbench/
├── data/ + engine/ + models/ + integrations/  # 现有通用底座
├── token_reduction/                      # 相对独立、可迁移的压缩子系统
│   ├── contracts.py / identity.py        # token/layout/result 与 identity 契约
│   ├── methods/                           # PairSelect、pair merge、neutral baselines 等方法
│   ├── bridges/                           # VideoMAEv2、VideoMAE、TimeSformer、CLIP 等适配
│   └── registry.py                        # 显式方法名、版本、能力声明；按需要实现
├── research/                            # 只读探针、正常—异常比较及诊断
└── paper/ 或 experiments/                # 通用运行编排、身份与导出能力
projects/icassp2027/                       # 本论文 profile、协议、冻结、suite、论文材料
scripts/icassp2027/                        # 尽量薄的入口及有历史身份的一次性工具
```

上图的 `methods/`、`registry.py`、`experiments/` 是**目标边界**，不是要求马上移动现有所有文件。当前 `src/vadbench/token_reduction/` 已有 `contracts.py`、`identity.py`、`pair_merge.py`、`token_selection.py`、`attention_diverse_selection.py`、`deployment.py` 和 `bridges/`；先保留现有导入可用，再在真实重复/耦合点上收敛。无需为每个方法建单独 Python package。

### 四条接口

1. **方法本体**只接收当前层 tokens、`TokenLayout`、预算和允许的当前层状态；返回缩短后的 tokens、layout、成员映射与成本遥测。不得依赖视频名、标签、数据集类别、正式 test 统计或未来层激活。方法的选择/合并公式、预算语义在此层。
2. **Encoder bridge**负责模型结构、token 顺序、CLS/特殊 token、位置编码、合法插入点、真实变长执行和 readout。VideoMAE 系列与 TimeSformer 不通过强行共享 reshape 伪装同一结构；不支持的路径显式报错。
3. **框架编排**负责从配置解析方法、挂载 bridge、抽取特征、记录真实 token 数/耗时/显存、持久化身份、复用训练与评测。ratio=1 与 observer 关闭的输出数值一致性是接入门槛。原有 `compression.py` 的缓存策略保持独立语义。
4. **论文项目**只提供选用的 encoder×dataset、冻结参数、head 训练预算、官方 UCF/XD 时间轴、图表和投稿出口。新数据集/新论文可引用方法本体而不导入 `projects.icassp2027`。

迁移判据：如果代码需要 ICASSP 的 UCF/XD 官方 split、六格矩阵或稿件文件名才能工作，它留在项目适配层；如果它只操作 `TokenLayout` 与当前层张量，则进入 `token_reduction`；如果它只关心标准 FeatureStore/检测头身份和 stage DAG，则进入框架编排。对现有 `paper/` 模块逐个按此判据审查，不机械整体改名。

### 兼容与测试

- 现有 `vadbench encoders list`、非论文 encoder 配置、FeatureStore 读取和旧 CLI 保持可用；新增入口可以引用旧模块，迁移完成后再清理确认无用的重复实现。
- 对每个已支持 bridge 测 identity、真实 `N_out < N_in`、坐标/特殊 token、head 输出维度、异常退出后 hook 复原；对可训练插件测梯度。对 CLIP 与分离时空布局分别测其真实路径。
- 方法迁移至少用同一方法在两个 encoder 上以同一规则运行，且不依赖论文路径；框架集成至少用另一数据集配置或合成 manifest 走通抽取→FeatureStore→预测的通用链。这里验证**代码可复用**，不暗示结果跨骨干等价。
- 原始哈希和冻结指纹不重写；若代码移动改变 code digest，新运行使用新身份，旧运行仍引用旧快照。只对已证明的窄范围兼容差异使用显式合同。

## 旧路径与新视图的切换

现有 `/users/fotile/datasets`、`/users/fotile/icassp2027-runs` 和 `/data2/localdisk/fotile-icassp2027-*` 在各类 writer 退出前保持原位。迁移一个完整 run 时，以**整个 FeatureStore 根目录**为单位搬运，先在新根打开 index 指向的 blob 并核验源/目标 digest，最后在旧路径建立兼容链接；不得先删除旧目录再修补断链。正式视图的相对 `shards/...` 路径必须实测可解析。节点可见性与 mount ID 写入 catalog，不能只凭两节点都存在 `/data2` 字符串就认定同一资产。

## 数据集规范

每个数据集有一个 `dataset_id + version`，包含 raw root、split 清单、来源/授权、视频 ID 规则、近重复组、时间轴协议、审计摘要和状态。推荐版本不是靠目录名 `official-verified` 自动决定，须以 manifest 覆盖、解码 QA 和冻结协议共同核实。

| 数据集 | 必留身份 | 不可混淆的内容 |
|---|---|---|
| UCF-Crime | 官方 train 1610、test 290 的 manifest 与视频路径；原始 1-based inclusive 时间标注及内部 `[start-1,end)` 映射 | `confirm64`、`neutral26` 等只是训练内子集/对照，不作为 full-train；`VAD/data/raw/ucf_crime` 现为链接 |
| XD-Violence | original declared 3954、accepted 3950、excluded 4 的文件级清单；test 800；raw→canonical 对齐回执 | 原始与 canonical 时间轴、step AP 与其他 AP 实现、压缩特征和原视频不混写 |
| CLIP–DSANet 输入 | 所用 UCF/XD 视频版本、十 crop、帧组与作者 checkpoint 来源 | 不与 V2/VMA/TS 的 pooled clip 特征共用同一 feature ID |

数据目录按 `raw/`（原始或解包后的不可变视频）、`manifests/`（split/角色/排除）、`annotations/`（按权限分开）、`audit/`（解码/覆盖/时间轴）、`derived/`（生成的视图）理解。Git 只保存小清单和引用，不纳入原视频、下载归档或大特征。原始视频的重复副本先用大小、来源、hash/部分 hash 和 video ID 对齐，标 `duplicate_candidate`；未经完整验证和明确批准不删。

## 特征规范

特征 catalog 的唯一 `feature_id` 至少由如下字段确定：

```text
dataset/version/split + encoder/runtime/checkpoint + preprocess/crop
+ representation/readout + sampling/time coverage
+ method/version/position/budget + calibration identity
+ source run + index/contract digest
```

每条特征记录指出 `data_format`（现有 FeatureStore `.npz`、DSANet `.npy` 十 crop 等）、blob root、index、resolved 配置、完成合同、QA、dtype/shape、视频/clip/帧覆盖、producer 是否已退出、节点可见性。`status` 区分 `complete_verified`、`complete_unverified`、`partial`、`failed`、`superseded`；同一个物理 blob 可被多个经过明确验证的只读视图引用，不为了“标准化”重复复制。

保留原 `.npz`/`.npy` 格式。统一的是元数据和访问视图，而不是强行重编码所有历史特征。对 dense 与压缩方法保持各自 fingerprint；head 的训练特征、评估特征与显式兼容许可一起引用。验证顺序：manifest 成员 → index 唯一键/覆盖 → 路径可打开 → shape/dtype/finite → 身份摘要 → 抽样重算或现有 SHA/QA → 完成合同。没有完整证据就标待验，不以视频目录数代替正式完成。

## 实验运行与论文追溯

统一 `run_id` 是一个不可覆盖的实验身份，包含目的、正式/开发角色、数据/特征/代码/环境/权重/方法/head 指纹、输入 run IDs、状态和原始目录。正式计时另记录 GPU UUID、独占性、batch、计时边界及插件开销。质量导出记录测试协议和 video-level bootstrap。论文表中的每个数字可从导出回到原预测/计时，再回到特征和源视频；缺失链条时该数字标 `unverified`，不拿另一轮结果补位。
