# 03｜实施、切换与验收清单

本页规定整理顺序和验收依据。2026-09-26 的源码/数据入口切换、6根同盘物理归档、双节点检查与测试见 [执行状态](EXECUTION_STATUS.md)。实际采用目录级原子交换保留inode和硬链接，并保留旧路径；归档没有把历史未核验blob升级成已通过科学QA。具体实现调整和维护窗口在 `progress.md` 与机器回执中记录。

## P0：冻结现场与确认写入边界

1. 在本地、node2、node3 分别记录 `git status --short`、关键路径 `realpath`、挂载/剩余空间和本研究 writer 的 PID、完整命令、日志/输出根；区分活跃、守护等待、已完成和别的项目进程。
2. 扫描 [01](01_资产清单与分类.md) 的所有源根并建立 `roots`、引用反查、初始目录文件数/字节数与小文件 SHA。扫描动态目录时标采集时间和不稳定状态。
3. 指定**不可改动源根**和待执行整理时的新 catalog/视图写入根。核对运行中的 writer 没有写同一个 FeatureStore index，旧结果不被新整理脚本覆盖。

**门槛：**每个源根的 owner、状态与被谁引用可查；活跃 writer 对应目录禁止移动或重命名。未知 writer 不视为空闲。根盘与数据盘有足够空间容纳清单和必要的临时视图。

## P1：确定权威源码与兼容基线

1. 对比本地当前工作树、远端 `/users/fotile/VAD`、`/users/fotile/icassp2027-runs/project`、正式 run 实际指向的 `code-*`。按模块记录：当前框架已有、论文新增、仅运行快照存在、已替代、未确定。
2. 将每个正式 run 的代码 SHA/dirty 补丁、解释器、依赖版本、模型权重与原始回执绑定。禁止为了“统一版本”改写旧 resolved/指纹。
3. 选定新的工作源码起点，先在独立工作区实现。合并时保护本地和远端未提交改动；不用强制 checkout、reset 或全目录覆盖。

**门槛：**六格压缩实验、CLIP–DSANet 补充实验及其论文数字都能追到执行时的代码；框架原有 CLI、非论文 encoder catalog 和 FeatureStore 行为有可复现的回归基线。若任何正式 run 代码身份未明，先标 `unresolved`，不据其迁入方法实现。

## P2：代码整合与中等解耦

按 [02](02_目标架构与数据规范.md) 的四条接口逐组处理：

1. 固定 `TokenLayout`/reducer 结果、方法身份与预算口径；清理直接相关的重复逻辑。方法本体不读论文配置或标签。
2. 把 encoder 差异放入 bridge，保留已核实的结构、位置和 readout 规则。先保持旧调用路径或提供窄兼容导出，再迁移调用方；没有必要的抽象不新增。
3. 让抽取、训练、预测、质量和效率从框架通用主链接口调用 reducer。ICASSP 的 dataset/head/冻结协议保持在项目层。`scripts/icassp2027/` 中可复用功能进入框架，历史一次性脚本保留为复现入口。
4. 将主方法及 neutral baselines 注册成可枚举配置。CLIP/DSANet 如使用不同视觉路径，显式声明能力；不能为凑通用性静默降级到 dense 或改动方法。

**门槛：**ratio=1/identity 数值一致；每个支持的 bridge 真正缩短后续合法计算并记录 `N_in/N_out`；方法在至少两种 encoder 上使用同一核心规则；完整链从原始视频/manifest 到 FeatureStore、head、预测和评估可运行；旧非论文能力回归通过。Python 改动后运行受影响测试及 `python -m compileall src tests`。原有冻结结果只做只读复核，不因新代码通过而宣称数值相同。

## P3：规范数据集与特征入口

1. 为 UCF/XD 定义唯一推荐 raw view、冻结 manifest、时间轴协议、排除项和 audit；复核 `data/raw` 现有链接。旧子集和下载归档只标角色，不删。
2. 为每个已有特征根建立 `feature_id` 与 `features.jsonl`，分开 dense、三种压缩方法各预算、各 encoder×dataset、CLIP 十 crop。保留 shard/merged/source run 关系及失败/partial。
3. 对完整视图逐一验证 index 到 blob 的可解析性。仅在 producer 全部退出、完成回执一致后生成新的只读链接/视图；源 index、blob 和合同保持不变。
4. 对每个目标格做覆盖与格式 QA；关键方法的测试特征只检查身份与覆盖，不读取分数来改变方法。迁移至 `assets/features/` 时一次处理完整 FeatureStore 根，保留旧路径兼容链接，并核验 index 中的相对 blob 路径。

**门槛：**UCF 官方 train/test 与 XD accepted train/test 的视频集合、交集、排除 4 个、clip/帧覆盖、shape/dtype、fingerprint、原始时间轴和完成状态有机器可读 QA；每个推荐 feature ID 能打开实际样本；`partial`/`failed` 不能被推荐视图吞掉。只有完整全量训练特征可标正式 head 输入。

## P4：整理全部实验与文档

1. 从每个实验目录的 resolved、status、日志、checkpoint、completion 和输出反建 DAG：`dataset → feature → head → prediction → evaluation/benchmark → export → manuscript`。把正式、筛选、pilot、失败、重试、旧版分开。
2. 对所有 `code-*`、调度器、DSANet campaign、六格压缩、预算 sweep、性质探针和旧 V-JEPA 观察建立 run 条目。目录没有 completion 的，保留 `unverified`，不靠名称猜测。
3. 按 [04](04_实验与文档重编.md) 给每份文档建类型/日期/状态/替代关系。删除已汇总且无独立引用的过时接管/即时调度文档；更新当前导航，标清 V2/V3 和后续实际范围变更的历史位置，冻结 JSON/旧 SHA 不追溯改写。论文稿件每个数字链接到审核过的 export。
4. 对清单运行漏项检查：目录→catalog 和 catalog→目录双向核对；配置/日志中的绝对路径引用反查；重复命名、断链、孤儿 checkpoint、孤儿特征均出报告。

**门槛：**“全部”以扫描范围内**每个目录可分类且每个被引用资产可解析**来验收，不要求所有历史运行成功。未识别或有争议的条目列 `unclassified/unverified` 清单和处理人，不能静默遗漏。文档有一个当前首页；历史与投稿材料均可查。

## P5：切换与稳定期

1. 先用新的目录/catalog 跑只读 smoke：加载原始视频、读取每类特征、重放一个已冻结 head 的预测、核对已有正式导出 SHA；不重新选择方法。
2. 在无 writer 且 P2–P4 验收通过后，更新默认配置与 README 指向统一入口。保留旧绝对路径的链接或映射，检查已有脚本和模型回执能继续读取。
3. 连续观察一个实际运行周期的新增 run：产物写在新规范位置、旧索引仍可读、没有重复 writer/断链。记录切换时间、代码/配置 SHA 与回退入口。

**回退：**切换失败时恢复此前链接/配置快照。每批跨文件系统复制须先核对源/目标摘要及 QA，再切换读取；同文件系统移动须保留旧路径兼容链接和迁移记录。用户已允许清理源码压缩包与多余文档；大特征、原始视频和正式 run 的重复物理副本在完整 SHA、引用和空间收益复核后才逐批删除，绝不把一个原始 run 的唯一副本当作“重复”处理。

## 优先级与工作量

先完成 P0/P1，因为远端旧框架与本地/运行快照不同且有未提交改动；这是最大合并风险。P2 可在隔离工作区进行，P3/P4 的只读编目可同步推进，但任何物理链接切换都要等 producer 状态和引用 QA。预计工作量取决于全量目录/文件数、需补的 SHA 与活跃作业，**目前没有可靠时间估算**；P0 清单出齐后再按数据量、测试覆盖和并行 writer 估时。
