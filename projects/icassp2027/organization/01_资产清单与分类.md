# 01｜资产全量盘点与分类

## 盘点边界

以 `/users/fotile/VAD`、`/users/fotile/icassp2027-runs`、`/users/fotile/datasets`、`/data2/localdisk/fotile-icassp2027-*` 为首批根；再从已有 `assets.local.yaml`、resolved 配置、软链接、run manifest 和日志中的**路径引用**反查遗漏根。分别在 node2/node3 核对挂载和 writer。不得扫入其他用户目录，也不得因某目录名字含 `icassp` 就认定它属于本轮正式结果。

远端 `/users/fotile/VAD` 是旧工作树，当前 `git status --short` 有修改；本地工作树也有大量未提交及未跟踪文件。因此源码清单必须同时记录服务器当前工作树、本地当前工作树、各 `code-*` 快照和它们的 Git/SHA 身份。不能只拿 `HEAD` 比较，也不能直接用旧服务器根覆盖本地代码。

## 全量清单的交付文件

执行阶段生成小型文本/JSONL 索引，放在 `projects/icassp2027/organization/inventory/`；大哈希清单及包含本机绝对路径的副本放在数据盘的受控目录，不进入 Git。所有扫描记录采集时间、主机、命令和扫描范围，避免把不同时间点的动态目录当成同一快照。

| 清单 | 一行的最小字段 | 完成条件 |
|---|---|---|
| `roots.jsonl` | root、owner、mount、用途、目录/文件数、字节数、是否有 writer、扫描时间 | 四类源根及配置引用到的额外根全覆盖 |
| `code_snapshots.jsonl` | path、Git commit、dirty diff 摘要、关键文件 SHA、引用 run、用途 | 每个活跃/已发表 run 可追到精确代码；未知标 `unresolved` |
| `datasets.jsonl` | dataset、version、role、raw root、manifest/split SHA、期望/实际视频数、排除清单、时间轴协议、许可来源 | UCF/XD 的推荐版本唯一，其他版本注明历史/子集/归档 |
| `features.jsonl` | feature ID、source run、dataset/split、encoder/checkpoint、preprocess、sampling、readout、reducer/budget、fingerprints、index/contract/receipt、视频/clip 数、dtype/shape、状态、blob root | dense/各压缩档/CLIP 十 crop 全可定位，partial/failed 不藏匿 |
| `experiments.jsonl` | run ID、阶段、输入 feature IDs、head/checkpoint、配置和代码 SHA、日志、结果/导出路径、状态、是否正式、test 使用范围 | 每个实验目录恰有一条身份记录，可从论文数字反查原始 run |
| `documents.jsonl` | 路径、标题、日期、文档类型、当前/历史/冻结/投稿、权威替代关系、引用的 run/decision | 不删除旧计划，当前入口无互相冲突的“最新版本” |
| `references.jsonl` | 源文件、被引用绝对/相对路径、是否存在、指向的 canonical ID | 找出搬迁会断掉的路径和符号链接 |

大文件哈希在迁移或冻结时按优先级计算：首先校验正式特征 index/contract、最终 checkpoint、正式导出及论文证据；对原始视频和海量 blob 使用已有逐文件 SHA/回执，缺失时分批补齐，不能因为全盘 SHA 耗时而跳过路径与覆盖检查。

## 实验分类规则

| 类别 | 例子 | 保留方式 |
|---|---|---|
| 正式原始运行 | dense/压缩提取、full-train head、正式预测、独占效率 | 原目录不可变，登记完整依赖图与 QA；发布的只是指向它的 catalog 条目 |
| 正式派生输出 | 质量矩阵、bootstrap、论文表格/图、manuscript evidence snapshot | 记录生成脚本及输入 run IDs；有独立 SHA 和导出日期 |
| 开发/筛选 | 64+64 screen、pilot、probe、neutral control、预算探索 | 标 `development`，不混入正式 full-train 或 test 主表 |
| 失败、partial、重试 | 旧调度 attempts、排除/隔离目录、失败 head | 原位保留状态与原因；新成功 run 通过 `supersedes` 引用它 |
| 源码/环境快照 | `code-*`、依赖锁、容器/解释器、权重来源 | 作为复现资产引用，不当成“实验结果”或盲目并入当前源码 |

同一 run 的目录名、日志名或修改时间不足以判断正式性；以冻结协议、resolved 配置、completion/QA、输入输出身份和论文导出链共同判定。没有证据的状态写 `unverified`。

## 文档分类与入口

| 目标位置 | 放什么 | 处理原则 |
|---|---|---|
| `projects/icassp2027/README.md` 和 `progress.md` | 当前导航与最新状态 | 只链接本计划及已核验结果，不复制长流水账 |
| `projects/icassp2027/decisions/` | 方法冻结、数据和评价协议、SHA 绑定合同 | 原件不改；补索引解释 superseded 关系 |
| `docs/icassp2027/` | 可复用的研究/执行说明 | 标注哪些是设计、哪些已实现；保留历史版本 |
| `projects/icassp2027/manuscript-20260922/` | 投稿正文、源图、表格及 evidence snapshot | 与工程文档分开，数字逐项反查 exports |
| `projects/icassp2027/organization/` | 本次目录、架构和迁移计划及清单 | 执行后更新状态，计划原文留痕 |
| 历史计划/交接包 | V2/V3、handoff、zip、旧 `docs/progress` 等 | 索引中标历史和替代关系；未经核验不删除或改写 |

文档检查要发现相互矛盾的“当前计划”说法；按 [04_实验与文档重编.md](04_实验与文档重编.md) 将过时接管/即时调度文档的独有事实汇入新说明，删除无独立用途的副本。冻结合同、原始回执和稿件源保持可追溯。论文引用、数据协议、实验身份应直接链接唯一的机器可读回执。
