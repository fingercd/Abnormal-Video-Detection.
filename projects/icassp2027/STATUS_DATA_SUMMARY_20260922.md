## 4. 今日事件记录：6 个压缩预测失败 → 窄豁免 → 全部恢复

**现象**：09:53–11:07，UCF×VideoMAE、UCF×TimeSformer 各 3 个方法的压缩预测全部在开工前的兼容校验处失败（`direct_insert may only change the reducer; backbone, output_dim, precision, and position_strategy must match`）。调度器每任务仅一次尝试机会，失败后不再自动重投。

**根因（已证实，纯记账问题，零科学差异）**：该校验按原始字节给代码算指纹。VMA/TS 共用的同一个适配器包装文件在 dense 训练侧是 **LF 行尾**、在压缩提取侧是 **CRLF 行尾**；文件内容逐字节一致（`diff` 为空，0 行不同），却被判成"两个代码版本"。两侧的模型权重、transformers 骨干、处理器、模型配置、依赖库版本全部一致；VideoMAEv2 三边原生一致，不受影响。

**证据强度（用仓库原装哈希函数复算，非类比推断）**：

| 证明项 | 结果 |
|---|---|
| 两版本文件去行尾差异后对比 | 0 行不同 |
| 同一文件 LF/CRLF 双形态哈希 | 分别等于 dense 侧/压缩侧记录值 |
| XD-VMA dense 训练视图全部 68 个源运行复算 | 均等于 head 记录值 `9a23c5da…` |
| XD-TS dense 训练视图全部 135 个源运行复算 | 均等于 head 记录值 `7f9a3ac6…` |
| 上述源运行与压缩侧其余全部指纹输入 | 仅差该包装文件 LF/CRLF |

**处置（用户拍板走窄豁免，未留决策文档）**：`src/vadbench/paper/compatibility.py` 的 direct_insert 校验加入**仅 3 对**已证明"仅行尾不同"的指纹放行表；runtime_id / weights_digest / preprocessing / readout / output_dim / precision / position_strategy 全部仍严格比对，差任何一项均不放行。补丁已同步至远端评分快照（`code-kimi-adgs-20260921`），原版备份为 `compatibility.py.bak-pre-lineending-equivalence-20260922`，可随时回滚。未改动任何运行中任务的记录与数据。**2026-09-22 16:0x 更正**：本文件原写作"4 对"，系计数错误。正确口径由 6 个 dense head 的 `checkpoints/final.pt` 元数据实推：VMA×UCF `81e31440…↔30fe33c1…`、VMA×XD `9a23c5da…↔30fe33c1…`、TS×两数据集共用 `7f9a3ac6…↔e5fd0bdf…`；V2 两侧同为 `19720d4e…` 原生一致。18 路中 12 路（VMA×6 + TS×6）走豁免、6 路（V2）原生匹配。远端放行表实测含 5 个唯一摘要，所有 XD 评分日志 0 条兼容报错。
