# 性质先行与两种插件同源：用户七点澄清后的执行约束

日期：2026-09-18。本文落实用户最新七点要求，优先于旧记录中把paired_random和pair_linear
并列为正式两类候选的安排。四encoder与UR-DMU后端选择不变；不追溯改写旧冻结文件或结果。

## 1. 配对和权重的准确含义

四encoder共用UR-DMU的网络设计、损失与训练规则，各encoder、dataset、seed独立训练
匹配权重，不共用一个已训练参数文件。原公开UR-DMU权重对应I3D，不能跨表示空间硬套。
第一层Temporal Conv1d将输入D768或D1024映射到512，后续原网络结构相同；对应权重
shape为[512,768,3]或[512,1024,3]，不补零、不截断、不用strict=False掩盖不匹配。
这是控制任务后端设计变量，研究视觉encoder内部变化，不是声称后端参数跨encoder迁移。

## 2. 现有压缩原型的重新定位

现有观测只确认了VideoMAEv2中层attention相对更新在含异常视频中更强的模型内关联，
未确认四encoder共性；时间变化候选未通过预定独立确认。视频/clip级统计不能直接推出
token重要性。fit26的高/低信号保留没有超过局部随机对照的表示保持，普通均值合并也有
负结果。不能把这些记录改写为已证明的异常token压缩规律。

因此：

- `global_uniform`和`paired_random`是必要的压缩对照。
- 原`pair_linear`及其pooled MSE校准是可复用工程原型/对照，不自动成为最终可训练方法。
- 相邻pair和线性加权有中立操作实验的工程动机，但还没有满足“经确认性质推导规则”的
  科学依据。不得先选网络或压缩操作，再倒推一个正常—异常故事。
- 既有中间层、50%预算和校准权重记录其原实验身份；不自动锁定未来性质驱动主方法。

最终方法必须具有完整证据链：

```text
正常—含异常输入的真实观察
→ 匹配控制与独立视频确认，明确适用模型/层/条件
→ 可在当前层获得的性质指标
→ 受控干预证明该指标能指导压缩，而不只是分组相关
→ 同一机制的免训练版与可训练版
→ 固定检测后端下的质量、效率和同预算基线比较
```

没有通过前两层不能宣称规律；没有通过受控操作不能宣称可压缩性。
若证据仍不足，报告具体负结果和缺口，不把工程上跑通当方法成立。

### 四 encoder 共用同一种压缩机制（2026-09-19 用户再次明确）

最终主方法必须在 VideoMAEv2、TimeSformer、V-JEPA 2、VideoMAE 四者上使用同一种核心
压缩机制。统计量/评分规则、选择或合并算子及预算定义保持统一；不得分别寻找四套局部有效的
算法，再以一个方法名合并报告。bridge 只处理原生布局、坐标、特殊 token 和位置机制等必要约束，
不能在 bridge 内暗藏另一套评分或压缩策略。

免训练版与 LoRA 版也沿用这同一机制；LoRA 负责适应压缩，不增加新的选择网络。
确需按 encoder 校准的参数必须遵循同一预登记规则并明确披露，不能把参数校准变成按骨干换算法，
也不宣称跨骨干零样本参数迁移。最终层、预算及参数当前仍未确定。

当前两模型的探索结果只能作为局部线索，不能据此锁定最终方法。若缺少支持四者使用同一机制的
证据，应报告该缺口并继续允许的确认/中立干预，不以四套不同插件替代原定主比较。

## 3. 两种合法的同源关系

### A：同一压缩机制，增加训练适应

免训练版由确认性质决定压缩。训练版保持相同压缩机制，不增加独立选择网络，训练
明确列出的已有压缩参数或模型参数以适应缩减。若解冻原encoder，须明确它是压缩后
微调而非“只训练插件”，另设dense同训练预算对照，分离额外训练收益与压缩机制收益。
报告训练参数量、数据、损失、步数、耗时和显存。检测后端在主比较中仍冻结。

### B：同一性质，规则选择与学习选择

免训练版直接计算确认性质并做选择/合并；训练版的小预测器估计同一性质相关的决策。
两者使用相同部署可用信息、压缩单位、预算和后端；网络不是无根据地另建一个选择器。
须给出学习目标和该性质的明确联系，以及学到的选择与规则/性质统计的可核查关系。
只训练插件时原encoder和后端参数冻结，但训练图须允许梯度经过后续层回到插件。

用户随后明确倾向A，并提出优先考虑LoRA。因此主路线更新为：先确认可操作性质，形成
免训练压缩机制；训练版保持同一机制和预算，冻结原ViT基础权重及检测后端，只训练
ViT内部LoRA低秩适配参数。不添加新的token选择网络，B保留为历史备选，不作为当前主线。
如果两类版本出发点不同，不能仅以“一个训练、一个不训练”作为同一方法的两版。

LoRA通常减少可训练参数和优化器状态，但不保证训练吞吐或激活显存按同样比例改善，
必须实测。至少比较dense、性质压缩TF、性质压缩＋LoRA；另设dense＋同预算LoRA控制，
区分额外训练带来的改善与压缩本身的作用。固定后端检查点和后处理不变。

压缩规则仍须有性质证据；不能用LoRA修复一个没有依据的压缩规则后再倒称性质驱动。
LoRA的目标层、rank、缩放、损失和步数只在允许的开发数据上确定并在官方测试前冻结。
可优先验证压缩点后的适配以控制训练成本，但不把尚未验证的配置写成最终方案。
必须核对真实权重使用位置：VideoMAEv2部分投影走函数式linear，只包模块forward可能
不会生效；V-JEPA 2训练路径不能被原wrapper的no_grad截断。验证LoRA非零梯度、参数
更新、head/base冻结、保存重载，以及若合并LoRA权重时的前后数值一致和新权重指纹。

## 4. 执行顺序与数据等待

UCF已具备完整训练原视频，不必等待XD才能建立dense基线和继续性质研究。
XD下载、坏源修复和审计，与UCF基线/性质/免训练操作并行。TF无需参数训练仍需要真实
数据验证性质、选择规则和预算；不能在没有证据时提前把规则定好。
可训练插件也不必等XD完整后才开始；应在性质与免训练机制确认后，先用允许的UCF fit
数据训练。是否额外用XD训练必须另有明确实验身份，不能默默改掉跨数据集验证含义。

每组比较必须先建立原encoder＋UR-DMU的dense原值，再比较免训练版、可训练版。
质量包括UCF frame ROC-AUC/XD作者口径PR-AUC，效率包括encoder/adapter/完整detector
延迟、吞吐、allocated/reserved峰值，以及逐层token数和训练成本。论文原值不能代替本机基线。

开发阶段的基线检查和方法选择只用允许的训练/验证分区；正式官方测试指标在方法冻结后
按dense→免训练→可训练顺序报告。不能先看官方测试dense/插件分数，再用它们挑规则或网络。
最终完整官方train训练、固定head、三个seed、0.005容忍度与视频配对CI继续有效。
